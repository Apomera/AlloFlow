# Adapted Text enhancements — September 8, 2026

Implemented locally following the [enhancement review](review.md).

## Changes

- **One reading renderer:** ordinary, stacked bilingual and side-by-side layouts now share block rendering. Headings use semantic heading elements; numbered and nested bullet lists retain structure and explicit numbering; paragraphs and meaningful line breaks remain visible. Explain, Revise, Define, Phonics and Add to glossary retain headings, lists and emphasis. Fully emphasized sentences and speaker labels are not promoted to headings. Windows line endings and legacy HTML heading lines are normalized for display and playback.
- **Bilingual content retention:** tables remain present when switching layouts. Both versions use saved language labels and language/direction attributes. Unequal paragraph counts produce an explanatory notice and an explicit missing-paragraph placeholder. The renderer displays existing paragraph order; it does not claim to verify semantic translation alignment or introduce new generation-time paragraph IDs.
- **Keyboard parity:** bilingual sentence playback and glossary actions use the same controls as ordinary reading. Word modes have one tab stop per paragraph with Left/Right and Home/End navigation, visible focus, and Enter/Space activation. A skip control moves past passage controls. Links and other embedded controls retain their own keyboard behavior.
- **Multilingual word help:** word targets use `Intl.Segmenter`, retaining punctuation and whitespace as text. A fallback preserves text when segmentation is unavailable. Definitions now retain non-Latin letters, combining marks and single-character words. Define and Phonics use the saved language of the selected segment; selected phrases retain that language too. Keyboard-opened popups anchor to the word. Dismissed or superseded requests cannot overwrite a later definition or reopen a dismissed one.
- **Playback boundaries:** the shared sentence splitter recognizes additional sentence-ending punctuation and structural list/quotation boundaries while retaining protected links, citations, math and familiar English abbreviations. The same shared helper serves playback and preparation. Existing audio records are not deleted; changed sentence boundaries can affect which stored clip is requested.
- **Teacher comparison:** choose the original/source version and the adapted language explicitly. Where a source language is known, the automatic choice uses the comparable adapted language. Paragraph whitespace remains intact. Different-language and long-text comparisons show complete versions without misleading or expensive word-change highlighting. Word counts and review guidance support checking meaning and citations; they are not an automated accuracy verdict.
- **Reading comfort:** Narrow, Medium and Wide column choices are available alongside a direct Read & reflect entry. Column width lasts for the current mounted reader; no new device-wide learner preference storage was introduced. Mode controls wrap at every viewport width. Definition and phonics popups fit the viewport even with enlarged typography.
- **Build reliability:** `node dev-tools/build_adapted_reader.cjs` rebuilds the three changed runtime dependencies, synchronizes their desktop public copies, and updates only their host content-hash pins. Reader build outputs use atomic writes to avoid Windows file-lock failures. Other in-progress workspace changes were preserved.

## Verification

- **169 passing regression checks** across 13 suites: reading structure, table retention, bilingual keyboard actions, multilingual word segmentation and handler behavior, request ownership, sentence indexing, audio, instructional roles, rigor, and reflection workflows. [Results](final-tests.json).
- **Four Chromium viewport/type combinations passed:** 320px/16px text, 390px/24px text, 1280px/16px text, and 1280px/24px text. Checks used real React and the production table formatter. They verified table/list retention, keyboard sentence and word activation, reading width changes, comparison completeness/layout, no horizontal page overflow, popup bounds and no page errors. [Results](browser.json), [runner](browser.cjs).
- Generated-module JavaScript syntax, inclusion of the current source, exact public-copy parity and all three host cache pins passed. Scoped `git diff --check` passed. [Build checks](build-checks.json).

The first focused run passed all new behavior checks and exposed four obsolete source-shape assertions tied to duplicated rendering branches. Those assertions were updated or replaced by runtime behavior coverage. Browser checks exposed a nonwrapping control row; that was fixed and the complete browser matrix passed afterward.

These are component and isolated browser checks, not a full application, screen-reader, live speech-provider, export or classroom evaluation. Screenshots were captured; the local image-viewing tool could not open them because of its Windows sandbox initialization failure, so visual inspection is not claimed. No live AI requests were made during testing.

Nothing was deployed or committed. More ambitious generation-time alignment metadata and an AI-assisted meaning-change summary remain future design work; this implementation provides reliable rendering and explicit, bounded teacher comparison without inventing those assessments.
