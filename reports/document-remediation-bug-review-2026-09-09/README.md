# Document remediation bug review — September 9, 2026

Read-only review of policy `20260909-4`. Thirteen reproducible issues remain across the live candidate gate, baseline export checks, and optional rendered comparison. No application code was changed.

The live probes use the actual strict acceptance gate and `aiFixChunked` with its model transport mocked. Five harmful candidates were accepted; two controls behaved correctly. These findings establish candidate-gate failures, not a guaranteed downstream PDF or delivery outcome. Six baseline Chromium probes and five rendered-comparison probes establish the other findings. Native browser observations are saved with the cases. The reviewed MCP rejection-evidence, checkpoint, and completed-result reuse paths produced no new confirmed defect.

## Findings

1. **[P1] A native field label can be overridden by unrelated ARIA wording.** Adding `aria-label="Teacher name"` to an input already labeled “Student name” passes strict acceptance and is returned by `aiFixChunked`. The source's effective native name is represented as an empty ARIA name, so the replacement is treated as an allowed name addition. Resolve the source name with native-label fallback before permitting additions. [Source:10243](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/doc_pipeline_source.jsx:10243). Evidence: `native-label-aria-override` in [live probes](live-source-probes.json).

2. **[P1] Accessible field descriptions can be reassigned without rejection.** Changing only `aria-describedby="kg"` to `"lb"` passes, even though Chromium's textbox description changes from “Enter weight in kilograms.” to “Enter weight in pounds.” Both passages stay in the document, so the text/order checks cannot detect the reassignment. Preserve resolved description relationships while allowing consistent ID renaming. [Source:10229](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/doc_pipeline_source.jsx:10229). Evidence: `field-description-reassigned` in [live probes](live-source-probes.json), plus [native accessibility descriptions](live-description-ax.json).

3. **[P2] Exponents can still move within or between links.** A linked `x<sup>2</sup> plus y2` can become `x2 plus y<sup>2</sup>`. Superscript kind/content and numeric sequences match, then whole-link text replacement removes the attachment evidence; detached script nodes receive no reading-position markers. Both within-link and between-link probes were accepted. Preserve mathematical attachment before normalizing descriptive link wording. [Source:10384](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/doc_pipeline_source.jsx:10384), [Source:10407](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/doc_pipeline_source.jsx:10407). Evidence: [live probes](live-source-probes.json).

4. **[P2] Explicit roles can downgrade native table headers.** Adding `role="cell"` to `<th scope="col">` passes the strict candidate gate. Chromium exposes ordinary cells instead of column headers. The current guard rejects `none`/`presentation`, but assumes other roles preserve TH semantics. Validate the effective header role with the existing allowance for deliberate, constrained scope correction. [Source:10197](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/doc_pipeline_source.jsx:10197). Evidence: [live probes](live-source-probes.json).

5. **[P2] Baseline export acceptance can pass a table absent from accessibility navigation.** Both `role="presentation"` and `aria-hidden="true"` tables pass every baseline check with complete coverage, even though Chromium exposes zero table/header roles. The control exposes one table and two headers. DOM tag names, scope, text, and dimensions cannot establish table accessibility exposure. Check the rendered table/header roles and relationships as well. [Export:59](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/document_export_at_acceptance.cjs:59), [Export:77](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/document_export_at_acceptance.cjs:77). Evidence: [export probes](export-review-probes.json).

6. **[P2] A rendered text checkpoint can pass after losing a visible and spoken negation.** The documented `text`, `visible`, and `exposed` properties all pass for `<p>Do <span style="display:none">not</span> open the container.</p>`. `textContent` retains “not,” while the paragraph itself remains visible/exposed; actual rendered text and the browser accessibility snapshot say “Do open the container.” Compare the relevant rendered/spoken text or its descendant exposure rather than treating container exposure as evidence for all its words. [Rendered:62](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/rendered_document_fidelity.cjs:62). Evidence: `hidden-negation-in-checkpoint` in [rendered probes](rendered-probe-results.json).

7. **[P2] The `display:contents` text fallback ignores ancestor opacity.** A selected paragraph with direct text and `display:contents` still reports `visible:true` when its containing DIV gains `opacity:0`. Range rectangles remain nonzero and the paragraph's computed visibility remains `visible`, so the fallback misses the ancestor that makes the text invisible. Preserve ancestor opacity/visibility checks in this fallback. [Rendered:63](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/rendered_document_fidelity.cjs:63). Evidence: `display-contents-opacity` in [rendered probes](rendered-probe-results.json).

8. **[P2] Duplicate option values conceal a changed selected choice.** Switching selection from North to South passes `selected`, `value`, `text`, `name`, `role`, and `disabled` when both options have `value="direction"`. The selected observation records values only, so it loses which option the user actually selected. Preserve option identity/index and relevant label/group information as well as submitted values. [Rendered:67](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/rendered_document_fidelity.cjs:67). Evidence: `duplicate-option-values` in [rendered probes](rendered-probe-results.json).

9. **[P2] The synthetic root URL can make different relative destinations compare equal.** `./chapter.pdf` and `../chapter.pdf` resolve to the same URL under `https://rendered-fidelity.invalid/document`, so the `href` checkpoint passes. The saved source/candidate files are in the same directory and those relative paths identify different actual files. Preserve literal relative destinations or resolve them against explicit, appropriate document bases. [Rendered:31](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/rendered_document_fidelity.cjs:31), [Rendered:68](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/rendered_document_fidelity.cjs:68). Evidence: `relative-link-root-collapse` in [rendered probes](rendered-probe-results.json), including actual file destinations.

10. **[P2] Relative CSS assets evade baseline dependency coverage.** A relative `background-image:url(required-chart.png)` produces a complete pass with zero blocked requests and zero unresolved references. `setContent` uses an `about:blank` page, and resource enumeration only covers elements/attributes; no network request is attempted for this unresolved relative CSS URL. Give the document an appropriate isolated base and/or explicitly account for CSS dependencies. [Export:44](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/document_export_at_acceptance.cjs:44), [Export:138](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/document_export_at_acceptance.cjs:138). Evidence: [export probes](export-review-probes.json).

11. **[P2] Canonically equivalent table expectations can falsely fail.** An identical decomposed “Café” cell and expected value fail `html.table-1`: the actual matrix is normalized to NFC while the expected matrix is left untouched. Normalize both sides under the same policy. The PDF matrix comparison uses the same asymmetric pattern. [Export:73](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/document_export_at_acceptance.cjs:73), [Export:206](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/document_export_at_acceptance.cjs:206). HTML behavior was reproduced; the PDF observation is a code-level counterpart, not a new PDF reproduction. Evidence: [export probes](export-review-probes.json).

12. **[P2] Unrequested long text can disable an otherwise small checkpoint.** Identical main elements containing approximately 10KB of prose report `observation-too-large` even when the checkpoint requests only `role` and `exposed`. The size limit runs against every collected DOM value before selecting requested properties. Bound the selected observations so unrelated document text does not invalidate a role-only contract. [Rendered:72](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/rendered_document_fidelity.cjs:72), [Rendered:81](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/rendered_document_fidelity.cjs:81). Evidence: `unrequested-large-text` in [rendered probes](rendered-probe-results.json).

13. **[P3] Inert XML script data is classified as an executable dependency.** A `<script type="application/xml">` data block forces unavailable coverage even though a separate JavaScript-enabled Chromium probe confirms that its body is not executed. The narrow inert-type allowlist also needs to distinguish browser-executable scripts from other data blocks. [Export:114](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/dev-tools/document_export_at_acceptance.cjs:114). Evidence: [export probes](export-review-probes.json).
