# Prepared-card height and repeatable reader checks

Prepared help can use the visible viewport height on short screens or with enlarged text. At a 320x225 viewport, the prior 104.5px card showed its heading and picture area but no explanation. The candidate uses 209px with 8px margins; the first explanation line is visible immediately. Content, citations, image credits, interaction matching and audio ownership are unchanged.

This increment began as an isolated candidate on codex/prepared-help-context, based on e63e08d99f0e60b8fb16c8fc7767ee02ab12c5ae. It is now integrated into the newer shared reader after overlapping ownership was released, together with the subsequent activation/scroll fix. See ../prepared-help-deep-2026-09-27/README.md and completion.json for current validation and hashes. Evidence below records the original candidate; these are local results, not deployed-release verification.

## Change and evidence

- view_simplified_source.jsx:1250: optional short-viewport sizing in the existing popup geometry helper and viewport listener. Prepared cards alone opt in at the hook and JSX call sites. Below 28 root-font rem of visible height, the card uses the viewport height minus 16px. Ordinary lookup popups and roomy-screen anchoring retain their previous behavior.
- tests/prepared_help_popup_layout.test.js: six focused cases cover short and offset visual viewports, enlarged text, missing visualViewport, ordinary popup sizing and roomy-screen sizing. The pre-change reproduction failed four of six; its two unchanged-behavior cases passed.
- dev-tools/reader-prepared-help/: a stable current-source browser fixture, stress checks and a command runner. Input SHA-256s are recorded and drift fails the run. Requested missing engines fail clearly. The runner compiles JSX and CSS in memory, uses a disposable loopback fixture, and does not build runtime files, install dependencies or access saved app state/providers.
- package.json: npm run test:reader:prepared runs the focused tests and Chromium interactions, preview, list-layout and card-stress checks. Add -- --browser=chromium,webkit to exercise both installed engines.

WebKit exposed fixture timing assumptions in support cleanup and form changes: support invalidation removes the card in render, before the React effect calls the owned-audio cancellation callback. The stable fixture now waits up to one second for that callback before asserting its exact audio ID/count, and waits for the changed support attributes before reading them. It retains the failure on absent or incorrect cancellation. Initial receipts are retained rather than represented as a passing run.
