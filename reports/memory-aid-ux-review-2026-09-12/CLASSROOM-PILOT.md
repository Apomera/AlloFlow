# Memory Aid classroom evaluation

This is a prepared evaluation protocol, not a completed classroom study. The product tests establish software behavior; they do not establish learning gains.

## Prepare a fair comparison

Choose a short lesson and a small set of targets already appropriate for the class. Review the facts, mnemonic, mappings, and application guidance before using them. Check each actual generated picture for misleading details and correct its description.

Keep the facts, cue wording, practice time, and questions the same across the comparison. Use a saved copy with its picture removed for the text-only condition; regenerating the entire aid could change the mnemonic and confound the comparison. Use visual associations for this comparison, since structured letter mappings are themselves part of the cue.

Vary which condition a learner encounters first. Use comparable targets rather than immediately testing the identical target twice. Record prior familiarity and ordinary support needs so that differences are interpretable. Use anonymous learner codes in evaluation notes.

Observe learners finding their first cue, changing targets, choosing to keep or personalize a cue, starting recall, and returning to a target. Record where help was needed rather than coaching them through every control. Check keyboard use and the assistive technologies learners actually use.

## Recall and understanding

1. Let learners study the matched material for the same amount of time.
2. Use a supported recall round, followed by the fact self-check. Record support level; do not treat it as unsupported recall.
3. Use an equivalent application question requiring a new example, prediction, or explanation. Judge whether the explanation follows the lesson facts, independently of whether the learner can repeat the mnemonic.
4. Set a later review date that fits the class timetable. For example, assess after the next class and again the following week; these are practical comparison dates, not claims of an optimal spacing schedule.
5. Use recall without hints at the later review. Keep the original target order or use matching numbered print worksheets. Compare responses with a separate teacher answer key.

For application explanations, use the same simple rubric in both conditions: no supported connection, partial connection, or a clear application of the required facts. A learner's confidence or immediate self-check is not a mastery measure.

## Decide what to refine

Compare teacher effort, navigation problems, delayed fact recall, and application explanations separately. Review whether images helped particular targets or learners and whether an image introduced an error. A visually appealing image or a high image count is not evidence of better memory.

Keep examples of confusing cues and failed images for revision, without adding private practice responses to shared lesson resources. The app's saved recall attempts, application responses, and review dates remain in its existing private browser/profile storage. The print presets omit those records.

## Checks requiring a real environment

- Generate sample cues and pictures using the configured text/image/vision providers, checking actual pixels and descriptions.
- Exercise the full app, saved profiles, cloud delivery, and image-omission notices in the intended teaching environment.
- Test the finished flow with the screen readers and input methods used in class.
- Collect the classroom observations above before making claims about learning gains.

None of these real-user or live-provider outcomes was simulated or recorded as completed by the automated test run.
