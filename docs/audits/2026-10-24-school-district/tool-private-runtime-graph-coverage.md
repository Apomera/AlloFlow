# Tool-private loaders and worker import graphs

Status: source hardening and isolated validation; publication remains held for a coordinated generated-artifact rebuild. Nothing in this work deploys, pushes, publishes, or changes the live site.

The private classic loaders use the host's reviewed script dispatcher before assigning executable URLs. This covers DeviceStorage entry points, ConceptQuest teacher controls, educator AlloSheet, Bird Lab and reef companions, Raptor artwork/effects, Universe flight, Blockly, FreeForms, and document-processing libraries. Unknown code fails through the feature's existing error/retry path. Approved Desktop aliases select the bundled reviewed file rather than attempting an old CDN-relative path.

`runtime_graph_delivery_policy.js` snapshots three host-reviewed inventories. It verifies the complete selected graph's byte lengths and SHA384 hashes before creating executable Blobs, importing a module, or starting a worker. There are eight named graphs: Piper, Kokoro, Transformers 3.3.1, standalone ONNX 1.21.0, PDF.js, PDF rasterization, Tesseract, and DuckDB. The inventories contain 36 stored assets and one composite DuckDB WASM record. No response, worker message, downloaded child manifest, localStorage setting, model name, or query chooses new executable authority.

New engine/document runtime assets add 132,181,747 bytes (about 126 MiB) in each of the root and public trees. Existing DuckDB assets are reused. Runtime graphs load when the corresponding feature is requested and are excluded from startup precaching; checking a complete graph can increase that feature's first-use latency. The largest stored asset remains below the existing 25 MiB per-file deployment limit.

HTTPS and localhost use SubtleCrypto. HTTP classroom LAN clients use native Fetch integrity verification on in-memory Blobs; the verifier first proves that the browser accepts a known correct hash and rejects an incorrect one. Browsers that ignore integrity fail closed. This preserves LAN compatibility; it does not authenticate an HTTP-delivered host page. The reviewed host remains the trust root. Desktop runtime graphs use bundled local assets. The full inventory and host adapter contribute to the compiled policy identity.

Engine bundles preserve the existing distinct runtime versions and contain no residual module imports or worker creation. Their WASM glue is bundled, runtime WASM/data URLs are verified Blob bindings, and ONNX uses a single thread without the proxy worker. Dedicated worker bootstraps restrict imports, executable fetches, and child workers to their selected graph. Approved child workers receive the same restrictions recursively; raw classic library bodies are imported only under that bootstrap. These controls establish byte provenance and graph closure; they are not a sandbox for deliberately malicious code that has already been approved in the host inventory.

The canonical engine adapters use the named host APIs. Kokoro configures its verified runtime before model loading and handles disposal while preparation is pending. DuckDB verifies each existing WASM chunk and the reconstructed whole binary, then starts its guarded worker. A failure preserves dataset summaries and does not select an unsigned monolithic binary. Document rasterization passes data to a verified worker; Tesseract receives a verified worker/core/WASM graph. PDF.js calls explicitly disable evaluation, the workaround in [Mozilla's CVE-2024-4367 advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq). This change does not claim to upgrade all third-party dependencies.

`runtime_graph_host.js` owns preparation, cleanup, and leases. Disposing one consumer does not revoke another consumer's live assets. Pending disposal is a barrier before reopening; failed import, worker creation, or asset creation closes the affected session for a fresh retry. Blob acquisition buffers are released after the verified graph has been materialized.

The read-only release gates validate exact root/public/built runtime bytes, closed module imports, the embedded host block, and the compiled policy identity. `check_private_loader_coverage.cjs` also inspects guarded call sites in canonical and generated tools and checks the affected runtime/STEM mirrors. Refreshing an integrity manifest alone cannot approve old generated tool code. Normal build hooks can regenerate these artifacts later; this security task does not run those generators over other agents' work.

Validation uses synthetic local data and loopback servers. Evidence is stored under `tmp/private-loader-security-20261024/` and `tmp/document-runtime-security-20261024/`. The focused suites cover private-loader denial/retry, graph tampering, WASM parts, graph isolation, recursive worker guards, Desktop refusal/localization, host leases and disposal races, real ONNX identity inference across the preserved backends, Piper phonemization, PDF rasterization, Tesseract native memory/filesystem calls, and a real DuckDB classroom query. The final receipt records test counts and source hashes.

Final focused validation: 267 checks passed, including 33 native browser cases with no skips. Every native receipt matches the final policy source. The read-only coverage gate finds no missing canonical protections across its 17 targets and intentionally blocks 17 stale or mismatched generated/public artifact checks. `tmp/private-loader-security-20261024/final-coverage-receipt.json` records the exact validation groups, source hashes, publication holds, and the approved one-hunk restoration.

Native browser validation in this pass ran on Windows Chromium; the workflow keeps these tests in the existing Windows browser job. Full voice/model inference, GPU inference, and OCR with downloaded traineddata are outside this isolated validation. No voice models, tokenizer weights, document traineddata, student records, or production content were downloaded or uploaded for it. The new graph assets are runtime code, WASM, and Piper's eSpeak runtime data package.

Automatic approval review blocked updating the shared generated App.jsx, so generated hosts remain pending. An agent also initially patched one generated Whisper import hunk before correcting the canonical source. Following explicit user approval, only that hunk was restored to its original import. Whole-file hash verification proved the exact approved restoration and confirmed that the canonical source was unchanged; generated JavaScript syntax passed. Existing independent work and unrelated generated drift are not treated as security-test failures to repair in this task.

Before deployment: coordinate completion of active source work, review the affected source changes, rebuild tools and hosts, refresh integrity inventories against matching source/public bytes, and pass the mandatory source/artifact/runtime/release checks. Current isolated passes are evidence for these changes, not approval of a stale shared build.
