Track 18 — retry a failed teacher recording without recording it again

The isolated candidate retains one captured take when adding it fails and presents **Retry adding recording** and **Discard take**, including when narration is collapsed. Retry uses the same audio, sentence identity, duration and captured host callback; it does not reopen the microphone. The temporary scope is explicit: leaving/reloading the reading or changing its text/language clears the take. This is recovery for a captured recording, separate from the existing device-storage retry.

No shared reader, host, generated file, Git state, deployed app, saved user data or actual microphone was changed by this work. All edits and validation stayed under `.tmp/reader-recording-retry18` and this report directory. No other session was contacted.
