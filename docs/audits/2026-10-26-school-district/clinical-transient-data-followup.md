# Clinical credentials and temporary export data

October 26, 2026. Continued local security improvements for Gemini Canvas and the proposed Portland Public Schools, Maine K–12 workflow. This pass covers clinical form credentials, queued AlloSheet transfers, and temporary BehaviorLens clipboard/print content. Read-only coordination left CI, broad release reconciliation, private runtime loaders and cloud services with their existing workstreams. All reproduction and validation used synthetic records.

## Corrected boundaries

**Credentials in shared views.** Multiple clinical views can subscribe to the same protected workspace service. Previously, a password or recovery key typed in one view could survive another view's unlock/relock sequence and reappear in the first view. The preserved reproduction demonstrates reopening records without retyping that retained secret. Credential and deletion-confirmation fields now clear when the owning service, phase, workspace epoch or setup recovery identity changes. Clearing happens when each service update is received, including intermediate transitions React batches together. Initialization from a replaced service cannot overwrite the current view. Same-context edits and unsuccessful password attempts remain editable; saved records are unchanged.

**Queued clinical spreadsheet exports.** Previously, Dynamic Assessment could approve an export, queue its readable artifact while the AlloSheet popup started, and then send it after the workspace locked or Canvas record permission was revoked. The callback's later check was too late to prevent that transmission. The actual bridge now captures a strict synchronous transfer control, checks it before queuing and immediately before native `postMessage`, and drops rejected artifacts and controls while rejecting their receipts. Ordinary nonclinical transfers retain their existing behavior. Existing destination-origin, window and bridge-token checks remain in place.

Dynamic Assessment binds the export to its workspace epoch and current case/review context. BehaviorLens binds it to its workspace epoch, selected workspace identity and mounted view. A case switch away and back does not revive the previous queued approval. Both require the versioned guarded bridge; an older bridge cannot silently ignore the control. BehaviorLens retains its preview and export confirmation, then calls that bridge directly at the final transfer boundary. Its legacy host callback receives no clinical payload. These local exports do not require external-AI permission, and clinical AI remains disabled by default. Receipt/status updates also check the current context.

**Temporary clipboard and print content.** BehaviorLens's fallback clipboard textarea previously remained attached with readable text if selecting or copying threw. It is now blanked and removed in `finally`; focus restoration checks that the protected context is still current. Print failures now remove prepared text copies, print styles and listeners. Normal prints keep their prepared content until `afterprint`, while lock, normal close and unmount also remove it. Print CSS now respects a protected ancestor's `hidden` state, preventing the print path rule from revealing a workspace concealed during saving/locking. The original native print-media reproduction demonstrated that override.

## Validation

**114 tests passed across 10 files**, with no failed or skipped assertions in the selected final results. **29 native Edge checks passed**, and all **12 scoped asset/host integrity checks** passed. The four runtime modules parse and match their public mirrors. The three host files parse completely.

The popup harness exercises the actual bridge, protected service and native cross-origin popup messaging, using the actual Dynamic Assessment callback and BehaviorLens protected-transfer helper. It checks allowed delivery and zero queued disclosure after lock, Canvas-policy revocation, case changes and unmount for both features. Full BehaviorLens mounting, pending receipt feedback and unmount invalidation are covered separately by regression tests. The initial popup harness encountered an initial-navigation timing error before any assertion; its corrected readiness wait passed. No production code changed for that harness correction.

The credential browser harness mounts actual React boundaries over the real protected service, native WebCrypto and native IndexedDB. It reproduces retained-secret reuse on the preserved baseline and verifies cleared fields, corrected-password retry and saved-record preservation on the candidate. The clipboard/print harness executes the actual extracted helpers with native DOM and print media; clipboard and print calls are deliberately stubbed or made to throw. These are scoped synthetic checks, not district-account or real-printer validation.

The [validation record](clinical-transient-data-validation.json) records source hashes, final test reports, baseline failures, native-browser checks, mirrored assets and bounded host changes. Independent review found no blocking defect in the four production candidates. Test fixtures use the supported lower PBKDF2 work factor; production encryption defaults were not changed.

## Delivery and limits

Source and public copies match for the protected workspace, BehaviorLens, Dynamic Assessment and AlloSheet host bridge. The three host files receive only those four assets' integrity/size approvals and loader cache identities. Complete host parsing and the actual embedded policy validate these scoped updates. The existing discrepancy between each host's embedded policy and the canonical policy source remains for coordinated release reconciliation; this pass does not claim repository-wide release validation.

These changes clear application form state and temporary DOM content; they are not a guarantee of secure memory erasure, browser-password-manager control or staff identity. Checks prevent a stale queued transfer from being sent after its guard fails; they cannot retract a transfer, clipboard copy, print job or download already delivered. Exported files and independently retained destination copies remain subject to district handling and retention rules. No deletion schedule or remote cleanup was introduced here.

No commit, push, build, deployment, provider request or district-account change was performed for this pass. Canvas real-record access remains disabled by default. A verified release, actual managed Canvas workflow validation and PPS approval remain necessary before sensitive-record use.
