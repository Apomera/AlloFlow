# School Store + Print Lab: administrator walkthrough

For the simple five-minute presentation, use the [unified demo guide](school_store_unified_demo.md). The longer historical Print Lab route below is optional. From the repository root, run `npm run demo:school-store -- --legacy`, then open [the local demo](http://127.0.0.1:8767). Keep the terminal running; Ctrl+C stops it. Reset fictional records before rehearsing again.

This demo runs the actual School Rewards Apps Script business logic with in-memory substitutes for Google identity, Sheets, Drive, locks, and mail. It contains fictional school records. Nothing is emailed or sent to a printer. Its role selector illustrates the screens; real account permissions require a separate school deployment check.

Open **Store + Print Lab walkthrough** in the blue banner for the route and sample downloads. Allow 10–12 minutes. The original [five-minute store introduction](school_rewards_admin_demo.md) is also available.

## Prepare

1. Start with fresh fictional records. Avery has **60 points**; the store has **5 Notebooks**, costing **10 points** each. The shopping window and Print Lab are enabled for this demo.
2. Download the **sample STL** and **matching review handoff** from the banner. The sample is a closed, 20 × 20 × 20 mm tetrahedron. The handoff is generated by the same serializer and preflight engine used in Print Lab.
3. To show the design connection, import the sample STL into AlloFlow's **3D Print Lab**. Keep **1 mm per source unit**, review the 20 mm dimensions, run preflight, then download its review handoff. That handoff can be used instead of the ready-made one. Geometry World, Art Studio, and Architecture Studio also have local Print Lab handoffs.
4. Explain: “Recognition grows a student's balance. Print reservations protect points for an approved project. The store spends only the remaining available balance.”

## Present the complete process

| Role | Action | Expected result |
| --- | --- | --- |
| Staff | Award Avery **20** points with specific feedback. | Balance **80**. |
| Student | Show Overview and activity. Open **3D Print Lab**, choose the review handoff and matching STL, enter **PLA**, and submit. | Hash matches; private request is **Submitted**. No points spent. |
| Staff | Open Print Lab. Choose **Download model for review**. Explain inspection of the exact uploaded file in Print Lab and the approved slicer. Record verification evidence. | Asset becomes ready for quoting. The actual downloaded bytes match the upload. |
| Staff | Approve a **15-point** quote with a future deadline; enter fictional estimates of **2 g** and **20 minutes**. | Student receives a quote. In a live deployment, enter the reviewed material, printer profile and estimates. |
| Student | Confirm and reserve **15** points. | Balance **80**, reserved **15**, available **65**. A changed quote must be refreshed and reviewed again. |
| Cashier | Buy one **Notebook** for Avery. Review and confirm checkout. | Balance **70**, reserved **15**, available **55**; stock **4**. |
| Staff | Add to queue → Record print started → Mark ready → Fulfill. | Balance **55**, reserved **0**, available **55**. One print purchase and simulated receipt. |
| Administrator | Refund the fulfilled print. | Balance **70**. The Notebook purchase remains; stock stays **4**. |
| Administrator | Open **Admin setup**, expand the repository integrity section, and run its check. | **Ready**, with reconciled points, inventory and audit records. |

“Record print started” updates the workflow record. It does not operate a printer. Never treat a local preflight result or downloaded job ticket as permission to start hardware. The live workflow requires the school's trained operator and approved slicer settings.

If time permits, reset and demonstrate cancellation after reservation: the held points become available again without a purchase. Help in the portal explains role-specific responsibilities. The portal has complete English and Spanish text; the new local demo banner and presenter route are in English.

## Before using real school records

- Deploy the matching updated **Code.gs and Portal.html**, plus the existing Index.html and manifest, from `apps_script/school_rewards`. Both backend and portal must be updated for quote confirmation. Refresh open portal tabs after deployment.
- Confirm the managed deployment owner, domain restriction and administrator roster. Test two separate student accounts, staff, cashier and administrator accounts.
- Confirm private Drive sharing. The new checks stop setup or model storage when privacy cannot be established; review sharing with the deployment owner if this occurs.
- Complete a designated test purchase/refund and verify the actual school email receipt. The local demo simulates delivery.
- Have the print operator inspect a sample's dimensions, exact stored file, slicer preview, material and printer profile. Complete a supervised print and handoff using the school's established procedure.
- Review retention, backup/recovery and academic-year procedures with the school. Keep Print Lab off until its workflow is approved; the presentation server's enabled setting affects only its fictional repository.
