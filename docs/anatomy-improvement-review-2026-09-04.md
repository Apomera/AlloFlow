# Anatomy tool improvement review — 4 September 2026
**Implementation update:** Priorities 1–3 have now been addressed. Quiz questions retain their displayed order and feedback across answers and restored sessions; hidden flashcard announcements contain only the name and position; accepted retrievals refresh the review timestamp even when confidence stays unchanged. The findings and evidence below describe the earlier build. Mobile study modes now use compact system and learning-level selectors with a keyboard-accessible More controls disclosure. In the same 390 × 844 harness, Quiz and Cards begin at 446 px instead of 943 px, with 17 controls above the task instead of 47. Priority 6 is also complete: Cards keeps separate rounds for each system, learning level, and deck scope, including after saved sessions are restored. Returning restores card order, position, and rated progress, with answers hidden after a context change. Refresh round restarts only the current round using the latest ratings. Priority 5 is now addressed inside Cards as well: study tips and optional notes expand on demand, rating and navigation stay together, and Reveal/Locate have 44 px touch targets. Priority 4 is partially addressed: French, Latin American Spanish, and Arabic each now have 55 translated study labels and messages, including recall controls, review rounds, notes, confidence ratings, and accessible announcements. Arabic cards use direction-aware alignment and counters, and the keyboard skip link no longer creates horizontal overflow in RTL layouts. Broader anatomy content still needs translation. Behavioral checks are in [the learning reliability suite](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/tests/anatomy_learning_reliability.test.js).

The next pass should fix learning reliability before adding more modes. Three defects were reproduced: a correct quiz answer can display incorrect feedback, hidden flashcards announce their answers, and successful retrieval can leave a structure overdue. Application code was not changed during this review.

**Quiz correctness.** Open Skeletal → Quiz with no confidence ratings, then choose Skull for the first function question. The stored result is `{ chosen: 'skull', correct: true }` and the score becomes 1, but the rendered result says the answer was Mandible. The quiz pool is sorted on every render; recording the correct response moves Skull from unrated to Learning, changing the question at the same index. Feedback is recalculated against that new question. See [quiz ordering](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/stem_lab/stem_tool_anatomy.js:5203) and [feedback validation](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/stem_lab/stem_tool_anatomy.js:5323). Verify stable prompts, options, feedback, and scores through rerenders and reloads, across all four question types. Context changes should invalidate an old question deliberately.

**Hidden-answer announcements.** Opening Cards with Ribs first invokes “Ribs (1-12). You have 12 pairs of ribs that form a protective cage…” while the card remains hidden. Next announces the Skull function before reveal. These are calls to the actual announcement callback, rather than a manual screen-reader listening test. See [card activation](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/stem_lab/stem_tool_anatomy.js:2766), [announcement content](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/stem_lab/stem_tool_anatomy.js:5031), and [card navigation](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/stem_lab/stem_tool_anatomy.js:5516). Cover opening, Previous/Next, Random, Next unrated, and Locate while hidden, plus reading after reveal.

**Review clock.** Seed Skull as Learning with a timestamp ten days ago and answer correctly. The score increases, but `_confidenceAt.skull` remains unchanged. [The evidence helper](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/stem_lab/stem_tool_anatomy.js:5610) returns early when the confidence level does not change. The existing due policy is two days for Learning and seven for Got it. This helper also serves Spotter and recap activities. Verify evidence timestamps for correct Learning/Got it responses and unchanged-level misses, while preventing duplicate submissions from awarding extra attempts.

**Language and mobile findings.** The catalog count covers literal `t('stem.anatomy.…')` calls; it excludes other hardcoded English and does not establish that every language has identical omissions. Missing examples in all three sampled catalogs include Due for review, round help, keyboard help, Locate this card, and note instructions. Phone measurements use the local harness with the app's compiled stylesheet and one representative state per mode. Explore's selected-structure panel starts around 1,913 px down because the diagram precedes it. Cards already places its panel before the diagram; the remaining delay comes from controls above the workspace. A compact study header would address that delay.

**Validation and limits.** This review used a state probe, a Chromium audit of Explore/Quiz/Cards, a separate Chromium confirmation of the quiz defect, three translation-catalog checks, and visual inspection of the phone screenshot. Axe reported no violations in the sampled screens, with two incomplete checks per screen. This does not establish full accessibility conformance or replace screen-reader testing. Clinical accuracy, the full application shell, deployed builds, and 3D performance were not audited. No application behavior or permanent regression tests were changed.

Recommended sequence: quiz stability, hidden-answer announcements, and review evidence first; then translations and mobile simplification. Add behavioral tests with those fixes. Preserve per-system rounds after deciding how resumed sessions should behave.
