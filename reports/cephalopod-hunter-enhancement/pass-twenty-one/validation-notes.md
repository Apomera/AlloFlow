## Baseline interaction defect

`tests/e2e/cephalopod-shelter-feedback.spec.ts` uses one real free conch and one real uncollected landmark pearl. It first establishes grounded hints, then raises the actual player with counted Q input, verifies that the player remains inside horizontal pickup range and over two metres above the object, and sends real G input. Both objects correctly reject pickup. The test then descends with Z and verifies successful conch pickup/drop and pearl collection. Only the two hint assertions are soft, so the initial run can retain both defects and the positive controls in one evidence attachment.

The recorded initial run in `browser-initial-feedback.json` has one unexpected test, no flaky/skipped cases and no runner errors. Its only assertion failures are the two intended contradictions: the conch hint still says to pick up the shell, and the pearl hint still says to collect the pearl while actual G rejects each by height. The later successful controls and evidence attachment are present. This is baseline failure evidence, not a final passing result. Distances in the attached free-object snapshots are world coordinates; the carried snapshot's position comparison uses its new local frame and is not a reach assertion.

The first post-fix feedback run, retained in `browser-final-feedback.json`, also failed those text assertions, but source review identified a fixture issue rather than a continuing production failure: the existing `setActionPrompt('')` made the element transparent without clearing its old text. The snapshot had read hidden stale content. The corrected snapshot records both raw text and computed opacity, and treats a hint as displayed only when opacity is positive; all real positive/negative interaction assertions remain unchanged. A repo-relative `CEPHALOPOD_MODEL_SOURCE` override permits the identical corrected oracle to run against the saved baseline without replacing working runtime files. Both earlier raw runs are retained. Root also cleared obsolete prompt text in production for accessibility; that change does not replace the visible-state regression.

The corrected visible-state oracle was subsequently run against the saved baseline. The main task reports actual exit 1; `browser-initial-visible-feedback.json` records one unexpected test, zero skipped/flaky cases and no runner errors. ## Geometry and lifecycle coverage

`tests/cephalopodlab_sponge_geometry.test.js` contains five focused cases against the actual production constructor with bundled Three r128. It checks the complete twelve-shelter spawn plan and 36 ordered rejection-free fixture draws, the three real sponge variants, one independently owned opaque mesh/material per sponge, fixed geometry budgets, finite indexed surfaces, strict visible winding and unit normals, position-welded physical closure, deep actual cavity rays, actual inner/outer wall thickness, rolled rim geometry, ten continuous flutes, the existing root-to-floor offset and original envelope. It also verifies that static sponges bypass dropped-shelter expiry and that disposing one does not touch its neighbor. The environment author read-only reviewed these oracles; all five cases passed in the candidate and final focused CPU runs.

`tests/cephalopodlab_conch_geometry.test.js` contains six cases. It executes the actual complete shelter construction, preserves the two free conches and original random draws, and checks one opaque independently owned mesh/material, finite normals and visible triangle winding, a closed indexed shell, and the actual shared triangle edges at the spire/whorl/lip/cavity joins. Its aperture rays derive their axis from rendered ring vertices and probe the center plus four offsets; they must reach a recessed interior rather than a colored lid. It also checks the original size envelope, deterministic static buffers through carry/drop poses and actual production expiry just before, exactly at, and just after 60,000 milliseconds. Expiry must remove and dispose only the dropped conch, once.

`tests/e2e/cephalopod-shelter-visuals.spec.ts` is a low/balanced native pair. It uses the two actual initial conches and three actual initial sponges, moves one of each into a clear approach, and records real render submissions, compiled/linked native programs, enabled/bound position/normal/color arrays, finite nonsingular normal matrices, stable native buffers and static owned resources. Incidental predators are cooled down and existing rocks moved away for this diagnostic view; it does not claim to test natural-spawn composition.

The pair sends real G/W input to verify conch attachment, the common octopus's actual 15% carry slowdown, carrying camouflage, unchanged wobble behavior, real drop state and `IN DEN`, visible tradeoffs, and a countdown that freezes while paused and advances after resuming. Inspection changes the camera while preserving shelter poses. Reduced motion intentionally retains the existing carrying wobble semantics. The actual dropped conch is then backdated past its known life to exercise live removal and independently owned disposal; this avoids spending 1,200 rendered frames waiting sixty seconds. The exact life boundary belongs in the conch CPU suite, using the real age branch.

The actual sponge must remain static, provide camouflage and `IN DEN`, reject G pickup, and lose its protection when the player leaves it. The balanced case also enables larger text at a 390-pixel viewport and checks that shelter feedback fits between the HUD, mission and controls without horizontal overflow. Teardown requires the actual contexts and all tracked resources to be released. Video and trace are disabled, and root runs the cases serially without retries.

## Deliberately preserved behavior

- Pickup predicates retain their original strict horizontal and height limits. Only prompt eligibility changes to match them.
- A dropped conch is not eligible for re-pickup under the existing `state === 'free'` gate.
- Nearby free/dropped/static shelter camouflage and den eligibility are distinct. The camouflage height limit is 1.2 metres; placed/static den protection uses 1.0 metre. Native assertions do not describe all nearby camouflage as safety.
- Sponge camouflage currently applies throughout its spatial aura; the old stationary-only prose was not an enforced movement predicate.
- All visual constructors must preserve world RNG, resource ownership, spawn metadata and existing carrying/drop/expiry/grounding rules. No unrelated rig baselines are migrated.

The independent feedback review found one additional correctness issue before final validation: movement multiplies carrying penalty by the species' existing `carryCost`, but the first HUD/formatter implementation reported the unadjusted per-type cost. A common octopus carrying a conch loses 15% speed, a coconut octopus 4.5%, and a giant Pacific octopus has no carry slowdown. Root corrected display formatting and wiring to use that actual multiplier. The existing four-case helper suite's formatter case now covers all three values and zero/default handling; its case count remains four, and all four passed in the final focused CPU run. The native pair deliberately uses common octopus, where the measured .85 speed ratio remains correct.
