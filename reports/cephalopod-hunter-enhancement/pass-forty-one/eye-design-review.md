# Crab eye proposal

Accepted input: `73cc490a61ab9f2c0f85c8a0ab8478e242e7291a517148b5a3c3391b9ab09788`.

The current two eye meshes combine a colored stalk with a dark compact pupil. Their `MeshBasicMaterial` ignores the scene lights, so neither the authored curvature nor the smoothed vertex normals contributes to their shading. The proposal changes only those two material constructors to opaque nonmetallic `MeshStandardMaterial` with roughness `0.32`. The existing vertex colors retain the stalk color and dark eye color. Actual scene lighting supplies the highlights; there are no painted highlights, emissions, generated textures, or camera-dependent color changes.

Each eye is already a closed indexed 58-vertex surface: a 29-vertex stalk and 29-vertex pupil. The eye factory, attributes, normals, contacts, index spans, bounds, transform, spawn draw count, animation, and gameplay stay unchanged. Each crab still owns the same number of geometries, meshes, and materials. The lit material uses the ordinary StandardMaterial path already used by legs and claws. It adds no custom shader variant, attributes, custom uniforms, derivative hook, draw, or texture. StandardMaterial brings its normal light/roughness uniforms and more fragment work than the old unlit eye shader. No device timing claim is made.

Uniform roughness is intentionally the smallest reliable choice for the merged stalk/pupil mesh. Its cost is that the stalk also becomes moderately glossy. Native matched-light captures should decide whether this is restrained enough. A physically separate stalk/pupil roughness treatment would require an explicit exact per-part scalar attribute; one Uint8 per eye vertex would cost 58 bytes per eye (116 bytes per crab) plus a varying and shader hook. Part metadata is CPU-only. Geometry position or vertex-color heuristics are unnecessary and less durable, so they are not proposed.

The existing articulated-crab CPU contract should pass unchanged: it does not require a Basic material and its sentinel shader probes remain unmodified because this proposal adds no shader hook. The draft CPU test compares the actual current crab factory with its exact eye-material inverse, then validates the new surface contract. Root should integrate it only if a new regression assertion is helpful; existing geometry tests plus native shader/light and disposal checks may already provide sufficient coverage.

Review boundaries: repository inspected read-only; no repository changes, test execution, browser use, GPU jobs, previews, or captures performed by this agent. The parent owns integration and visual acceptance.
