# Local integration and commit scope

The shared host and HostHandlers source/runtime already contained other owners' pending changes at the start of this pass. Whole-file staging would include that work. A selective commit of different generated bytes would also differ from the actual candidate exercised by the regressions.

This pass therefore leaves its integrated production changes and tests local. `applied.json` contains the seven guarded before/after hashes and 45 exact source operations. `source-before/` retains the original current-file bytes; `initial-candidate/` separately preserves the first tested proposal before the independent Maine pin refresh. The established selective builder verifies the canonical/runtime pair, and the source hosts share the same content pin.

The existing assignment-readiness fixture changed only its request ownership bookkeeping and supplied bindings; its assertions remain present. That fixture's previous bytes are retained under `source-before/tests/`. Its adjacent Vitest rerun was not reached because the broader runner stopped at worker startup failures, so this report does not claim a green result for it. New regression suites and validation artifacts live in this report folder.

No files are staged by these helpers. No broad app build, commit, push or deployment is performed. A later coordinated integration can apply the recorded operations to a stable checkout, regenerate HostHandlers with the same builder and validate that concrete commit candidate.
