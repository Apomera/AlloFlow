What a packet is

A packet is one file that holds a short practice activity.

  1. You make one file

    Pick the activities and the words. The file is put together in your browser. Nothing is uploaded.

  2. A student opens it

    It opens in a web browser such as Chrome, Edge or Safari. The questions, the sounds and the scoring are inside the file, so it works with no internet.

  3. The student saves a results file

    At the end the student presses one button to save their results. You open that file in a spreadsheet: one row for each question.

Check it yourself

You do not have to take this page's word for it. Each point below can be checked in a practice file.

A practice file can

  • Play recorded words and sounds that are stored inside it.
  • Score each answer on the student's own device.
  • Keep the student's place on that device, so they can stop and pick up later. Start over removes it.
  • Save a results file to that device when the student presses the save button.

A practice file cannot

  • Run AI. Nothing is generated when you make a file or when a student uses it. The spoken sounds were recorded ahead of time with computer voices, including an AI voice.
  • Connect to the internet. The file tells the browser to refuse every connection, and the browser enforces it.
  • Ask for an account, a password or an email address. The student types a code name or a first name. That is all.
  • Use the microphone or the camera, or set cookies.
  • Be a secure test. The answers travel inside the file so that it can score them with no internet, and a results file can be edited. The check value in a results file shows accidental changes, not deliberate ones.
  • Run inside a file preview. Google Drive, Google Classroom and the iPad Files app show a preview that does not run. The file then shows a note that asks the student to download it and open it in a browser.

How your school's IT person can verify it

  1. Open a practice file and press About this file. It lists what the file stores, what it saves and the rules it gives the browser.
  2. Open the same file in a text editor. Near the top is a Content-Security-Policy line that ends with connect-src 'none'. That is the rule that refuses every connection.
  3. Read the code. The file has one script and it is not minified. The long runs of letters inside it are the recordings.
  4. Open the file with the browser's developer tools on the Network tab and complete it. No request leaves the device. Entries that start with data: are the recordings inside the file.
  5. Read the source. It is public: AlloFlow on GitHub, license AGPL-3.0. A practice file is built by word_sounds_packet_builder.js and word_sounds_take_home_loader.js.
