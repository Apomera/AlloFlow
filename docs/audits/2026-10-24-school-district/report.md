## PPS and Gemini Canvas approval requirements

PPS's published **GCSA-R Employee Computer and Internet Use Rules**, revised June 18, 2024, require prior authorization before staff use or encourage student use of online educational services. The policy also addresses authorization to disclose personally identifiable information, reporting security breaches, records preservation, and district control over enabled Google features. The current internal generative-AI guidance, service settings, and AlloFlow-specific authorization must be obtained from PPS; public availability of Gemini does not settle those questions. [PPS GCSA-R](https://www.portlandschools.org/about/board-of-education/board-policies/policy/~board/book-g/post/gcsa-r-employee-computer-and-internet-use-rules)

The public **2026–27 PK–12 software catalog lists Gemini as staff only** within Google Workspace Education Plus. AlloFlow was not found in the four published grade-band catalogs reviewed; that does not rule out a separately authorized pilot. The internal Staff Hub AI/software guidance requires login. Teacher authoring and student interaction with the generated app therefore need separate, explicit PPS review. Requests can follow the district's instructional-software/Help Desk review route. PPS's academic-honesty policy separately requires attribution for permitted student generative-AI use; instructional permission does not establish privacy or software approval. [PPS Digital Resources](https://www.portlandschools.org/department/technology/digital-resources), [2026–27 PK–12 catalog](https://docs.google.com/spreadsheets/d/e/2PACX-1vRrCjXRidXL0Op6V-mfBkVnYyqk0PdTJbnPeUl9OdUd94qV5uQ6IeOJIuJfbIJGc9zOjADwKEOpcUwU/pubhtml?gid=0&single=true), [PPS staff directory and software review route](https://www.portlandschools.org/about/staff-school-directory), [JICD Academic Honesty](https://www.portlandschools.org/about/board-of-education/board-policies/policy/~board/book-j/post/jicd-academic-honesty)

Google documents enterprise protections for the Gemini app used with qualifying Workspace for Education accounts. That supports the surrounding Gemini service's privacy posture. It does not by itself establish the contract covering every generated app request, injected API credential, external module, or provisioned Firebase database. AlloFlow's runtime AI code targets `generativelanguage.googleapis.com/v1beta`; the precise service classification and applicable terms need confirmation for the PPS Canvas instance. [Google Education FAQ](https://knowledge.workspace.google.com/admin/generative-ai/workspace-with-gemini/gemini-for-google-workspace-faq-education), [Gemini Developer API terms](https://ai.google.dev/gemini-api/terms)

Google's Canvas safety guidance distinguishes private storage from shared multi-user databases and warns that shared app data can be accessible through the app's public link. This is a platform-level warning, not proof that AlloFlow has exposed a particular record. It makes an actual Canvas authorization, sharing, storage, and deletion review essential before student records or live classroom traffic are introduced. Google also requires adults to add Gemini-powered features to Canvas apps; student access to the resulting features needs separate age/service review. [Canvas safety and security](https://support.google.com/gemini/answer/16419134?hl=en), [Canvas feature documentation](https://support.google.com/gemini/answer/16047321?hl=en)

The repository already recommends Canvas as a teacher-authoring surface and an owned deployment for student classroom traffic. That recommendation at [DATA_PRIVACY_POSTURE.md:74](/C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/docs/DATA_PRIVACY_POSTURE.md:74) should govern the proposed pilot until equivalent assurances for Canvas are demonstrated.

## Prioritized findings

Priority denotes the proposed release or approval gate, not a CVSS score. **P0** means resolve before the affected workflow handles identifiable or sensitive school records. **P1** means resolve before the relevant student-facing or broader production deployment. **P2** means complete as the supported deployment and assurance program mature. Operational unknowns are distinguished from confirmed source behavior.

**Acceptance:** PPS approves a versioned service map and feature scope, with each data destination tied to documented terms and an accountable owner.

## Sequence for readiness

1. **Before the pilot:** obtain PPS technology approval; freeze the teacher-authoring feature scope and approved content categories; resolve Canvas/API/storage terms; restrict unapproved AI/media/support routes; correct the clinical-redaction and no-server-storage claims. Use public or synthetic material until the affected P0 controls are accepted.
2. **Before student-facing live use:** select a district-approved transport/backend; verify effective identity, authorization, validation, rules, admission, quotas, sharing, and deletion; exercise shared-device and export boundaries. Do not automatically carry teacher-authoring approval into student interaction or clinical workflows.
3. **Before wider release:** complete immutable asset delivery, browser policy testing, release-specific vulnerability and package verification with the existing agents, and required signing/distribution work. Document remaining exceptions with owners and expiry dates.
4. **Before sensitive-record production use:** execute required agreements and purpose/consent approvals; demonstrate end-to-end record access/deletion and key recovery; exercise incident response and restoration; supply accessibility evidence for the approved workflows. Enable behavioral, psychological, photo/audio, and personnel features only under their separately approved scope.

The resulting district review packet should contain the release identifier, enabled-feature list, data/provider map, agreements, access matrix, retention/deletion results, synthetic security test evidence, deployment receipts, incident/restore results, accessibility evidence, risk register, and named operational owners. Maintain a distinct approval record for Canvas, hosted browser, Desktop, and school-owned services.
