# Memory Aid — returning learners and flexible recall

This pass removes friction found in the newly implemented workflow.

- **Resume directly into the application.** “Continue my application and plan” now opens the application section, scrolls it into view and focuses its summary. The explanation is next in keyboard order. Subsequent autosaves do not reopen the section or move focus. Starting a fresh attempt clears this resume behavior.
- **Keep writing when changing response modes.** Switching between written recall and responding another way retains the written draft within the open attempt. Switching back restores it. Completing a non-written response still saves no transcript; cached writing does not enter the private practice record.
- **Request a cue without restarting.** During recall without hints, “Show my cue” preserves the response, reveals and focuses the cue, and marks the eventual attempt as supported. It resets a prior non-written completion confirmation so the learner can finish responding after receiving help. There is no control that relabels a supported attempt as unsupported.
- **Make mobile recall more direct.** Repeated studio and target headings have been reduced during active practice. The remaining target label is numbered and does not disclose the answer. In the same 390 px authored fixture, the response field moved from 750 px to 599 px down the page—151 px earlier—while response-mode choices remain visible.

The source change is limited to `memory_aid_source.jsx`, its generated root/public module, and associated UI strings. Existing saved resource schemas and private practice formats are unchanged.
