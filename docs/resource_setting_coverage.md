# Resource × setting coverage (measured)

Generated by `node dev-tools/check_local_llm_resource_matrix.cjs --capabilities`.
**Do not hand-edit.** Regenerate after any dispatcher prompt change.

Each cell is measured by driving the real `handleGenerate` with a poison-pill value for
one setting and checking whether that exact string surfaced in a prompt sent to the model.
This is stronger than grepping a branch for a variable name, which only proves a mention:
until 2026-07-28 `concept-sort`, `dbq` and `lesson-plan` all interpolated `effCustomInstructions`
while the resolver had no case for them, so the value was structurally always `''` — grep said
covered, the teacher got nothing. Those three are fixed; the class is what this probe exists to catch.

✅ reached the model  ❌ never appeared  ❔ undecidable (nondeterministic prompt)

## Local/cloud prompt divergence

Many branches ship two prompts behind `if (usesLocalTextBackend)`. A source-text scrape
cannot tell them apart because both live in the same branch body. Divergence here means
the offline no-egress path silently behaves differently from the cloud path.

- none

_Excluded as unmeasurable (cloud prompt builders are stubbed in this harness): `lesson-plan`._

## What this probe cannot see

- `alignment-report` is absent from `CASES`, so 19 of the 20 dispatcher types are measured.
- `generateVisualPlan` is stubbed to `async () => null`, so grade/style values the **image** branch passes into it are never seen. Image `grade` reads X for that reason, not because the branch ignores it.
- `buildLessonPlanPrompt` / `buildStudyGuidePrompt` / `buildParentGuidePrompt` are stubbed to `json({})`, so **lesson-plan**'s cloud prompt is never built. Its cloud row is not evidence.
- `handleGenerateMath`, `handleGenerateLessonPlan` and `handleGenerateSource` are `noOp`, so any branch that delegates to them contributes no prompt.
- `getGroupDifferentiationContext` returns `''`, so roster-group text never appears.
- Retry/repair prompts and image stage 2 are not exercised.
- **note-taking** is measured on the `cornell-notes` template only (see its `CASES` entry). Its other five templates each build a different prompt — notably `q-and-a`, which does honour DoK as of 2026-07-28 but cannot show it here. Its row understates coverage.
- Canned model responses are fixed, so a branch whose prompt depends on an earlier response is measured against the canned one.
