# Independent review: form submission encoding

The new `accept-charset` normalization initially treated replacement-encoding labels as unsupported because `TextDecoder` rejects them. Chromium instead selects the encoding and converts it to UTF-8 for submission. The exact labels are `csiso2022kr`, `hz-gb-2312`, `iso-2022-cn`, `iso-2022-cn-ext`, `iso-2022-kr`, and `replacement`, as specified by the [Encoding Standard's label table](https://encoding.spec.whatwg.org/#names-and-labels) and [output-encoding algorithm](https://encoding.spec.whatwg.org/#output-encodings).

Native Chromium 148.0.7778.96 submitted `answer=caf%C3%A9` for every `accept-charset="LABEL windows-1252"` above. Changing it to `windows-1252` produced `answer=caf%E9`. Before the correction, the actual strict gate accepted both the `replacement windows-1252` and `iso-2022-kr windows-1252` changes, and mocked `aiFixChunked` returned the changed candidate. The control `utf-7 windows-1252` correctly fell through to Windows-1252 and preserved the payload.

These pre-fix observations were returned in tool output during review; no standalone pre-fix JSON trace was saved. Requests were aborted before network delivery. This note records the observations without claiming a persisted machine trace.

Read-only inspection of the correction confirms that all six labels now map to UTF-8 before `TextDecoder`, with ASCII-only case normalization. The shared fixture adds a harmful Windows-1252 change and an equivalent UTF-8 control for each label, plus mixed-case and unsupported-UTF-7 controls. The final review also retains an unsupported Kelvin-sign lookalike (`iso-2022-Kr`) as unsupported: its native output uses Windows-1252, not UTF-8. A harmful UTF-8 change and equivalent Windows-1252 control bring this addition to 16 cases. Existing UTF-16 and `x-user-defined` handling remains intact. Final focused verification passed all 63 unit fixtures and all 63 native Chromium cases, without retries. The source agent saved [compact verification](../../document-remediation-enhancements-2026-09-20/forms/replacement-ascii-verification.json) and per-case native observations in [replacement-ascii-native-tests](../../document-remediation-enhancements-2026-09-20/forms/replacement-ascii-native-tests/). I inspected the final mapping and fixture changes; no additional issue was found in this bounded read-only review. Final integration belongs to the root task.
