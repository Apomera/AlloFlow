# QUARANTINE — known-failing test files, captured 2026-07-26

# WHY THIS EXISTS
# The blocking CI job ran the entire suite with no allowlist while ~271 assertions were already
# red. A gate that is permanently red gates nothing: a genuinely new regression could not change
# its colour, and nobody could tell one from the other. That is how a dead image-splice regex and
# a wiped-out set of OCR disclosures survived for months (audit finding H1).
#
# WHAT IT MEANS
# Files listed here are EXCLUDED from the blocking `unit` job and run in a separate, non-blocking
# `quarantine` job so their status stays visible. Listing a file does NOT mean the code under it
# is broken — the large majority are raw-source substring pins that drifted away from the source
# they assert against (verify with: git show HEAD:<file> | grep -F '<pinned string>').
#
# RULES
#   1. This list may only SHRINK. `npm run check:quarantine` fails if a listed file now passes
#      (remove it) or no longer exists (remove it). Adding a line needs a reason on the line.
#   2. Never add a file here to silence a NEW failure. Fix it, or the gate is dead again.
#   3. Format: <path>  # <n> failing · <first failing test>
#
