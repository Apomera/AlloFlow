## What changed

**Consistent content preservation.** Whole-document fixes, normal chunks, split retries, image retries, and assembled output now use the same acceptance policy. Fragment handling permits missing document wrappers without relaxing text retention, growth, table-cell position, or image identity checks. Unsafe suggestions fall back to the original content. Valid header, alt-text, and whitespace repairs remain accepted. Both image placeholder families and embedded images retain exact identity and order.

**Physical-page OCR evidence.** Vision output must supply the expected page boundaries. Ambiguous multi-page output receives bounded physical-page retries; unresolved text remains separate from the page map rather than receiving guessed page numbers. Reconciliation retains pages recovered by either engine and avoids duplicating uneven page text. Comparison now flags conflicting words, values, dates, negation, and math operators even when text lengths match. Formatting-only differences remain normalized. Retry quota failures preserve pages already recovered, successful page retries clear superseded truncation warnings, and initial Vision work starts in batches of at most five requests.

**Durable rejection evidence.** The main remediation result records a total rejected-candidate count and at most 100 short records identifying pass, chunk, phase, and reason. Project autosave/import preserves these fields. MCP driver output, desktop and remote reports, and terminal checkpoint resume retain the same bounded evidence; older version-2 capsules default missing fields to zero and an empty list. Follow-up AI, Equal Access, and axe repair paths retain new evidence even when verification fails or a proposed round is reverted, while controller and document revision guards prevent stale callbacks from changing another run's evidence.

**Safer MCP resume.** Agent-bridge request IDs include a fresh attempt nonce, preventing an earlier attempt's reply from answering a resumed request. Durable jobs retain bounded numerical diagnostics. Terminal checkpoints retain source text and OCR warning page identities so final coverage checks have the same evidence after resume. Compact capsule version 2 retains the existing size limits; incomplete older compact capsules rerun safely. Cache identity also advances to invalidate results produced under the previous preservation rules.

**Truthful export verification.** A produced PDF with failed, unavailable, or skipped independent validation requires review. HTML verification remains separately visible. The remote producer and public report consumer share normalization and delivery decisions, including the finalization-reserve reason. Executed PDF evidence is bound to the output hash, byte count, profile, validator version, validation time, and duration. Missing counts, zero executed checks, contradictory reports, wrong profiles, and unsuccessful processes claiming a pass cannot produce passing evidence. Actual veraPDF noncompliance is preserved, including the exit 1 behavior observed in packaged veraPDF 1.30.2. Ace and EPUBCheck adapters reject malformed or contradictory execution evidence. Historical reports missing all binding fields remain retrievable as unavailable; partial or mismatched binding is rejected.

**Build and test maintenance.** The remote runner's staging manifest includes its required narration, accessibility-evidence, and verification dependencies and checks their exact bytes. The pipeline, audit view, and follow-up handler bundles are rebuilt with matching desktop public copies. Host JSX parses successfully. Fragile source-window/string assertions were replaced or corrected. Portable integration subprocesses now run asynchronously with explicit deadlines and cleanup, resolving the timeout failures from the review without changing portable production behavior. Title II fallback wording and English deadline strings are consistent with the official sources linked in the original review.

## Follow-on work and limits

This pass fixes the demonstrated failures and strengthens their regression coverage. A larger canonical document model with stable block/cell/asset IDs, incremental region audits, a representative production performance benchmark, and richer page/cell review controls remain follow-on work. Rejection-only metadata in the separate Workbench command API also needs a broader command-result contract; its content acceptance gate is protected by the shared checks, but that interface does not gain the main remediation flow's rejection-history persistence here.

The tests use local fixtures and scripted model responses. They establish deterministic preservation, resume, artifact, and report behavior; they do not establish live-provider quality, screen-reader usability, production latency, or full regulatory conformance. Windows ARM64 still cannot execute the installed Cloudflare workerd integration runtime; service type checks and the available public-report/runner contracts are exercised locally. A deployed release still requires the project's normal application and service release process.
