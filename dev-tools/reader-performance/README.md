# Reader performance fixtures

This is a disposable, local browser fixture for the reader component and its overlays. It uses synthetic readings, isolated browser storage, and a loopback audio route. It never loads the full host or the deployed release. External requests fail the run.

## Run

Use the existing dependency tree; no installation is necessary. From the worktree root:

```powershell
node dev-tools/reader-performance/run.cjs --deps C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated --validate
node dev-tools/reader-performance/run.cjs --deps C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated --smoke
node dev-tools/reader-performance/run.cjs --deps C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated --baseline-ready <full-HEAD> --output reports/reader-performance.json
```

`--baseline-ready` records the exact inspected HEAD. It is an explicit baseline identifier, not a dependency gate. The run fails if HEAD or measured source changes while it runs. `--baseline-source` reads the reader and helper sources from that HEAD with `git show`; it does not change the checkout. Omit it to measure the working files. `--instrument` enables the profiling React build, public-helper counters, storage counters, and timer/rAF tracking. Compare timings from runs with the same instrumentation mode. `--case` accepts comma-separated case names. `--browser` defaults to `msedge`.

The runner bundles JSX in memory, uses the checked-in CSS, starts an ephemeral loopback server, opens a new browser context per case, then closes the browser and server in `finally`. JSON reports record source/CSS hashes, hardware and browser versions, and hashes of the four harness files. There is no app build or generated-module mutation in this command.

`--retention` adds a fixture-only probe for the reading-place cache: entry count, total exact-text key characters, and counts of authored/recovery entries. It does not expose text or add a production API. Use it with `--case unique-navigation --instrument` to compare pristine-cache growth. Only never-saved, empty, position-free entries are disposable; authored work, saved baselines, positions, pending writes, removal markers and recovery evidence stay in page memory. The default pristine-entry limit is 20, not a limit on total session memory or bytes. Compare equal instrumentation modes and source hashes; residual heap growth is not proof of a leak or a lifetime memory bound.

## Scenarios and measurements

The 20 cases cover 30/300/3,000 sentences; 0/30/200/1,000 anchored supports; separate original-source and comparison-source support workloads; a long crawl; a closed outline; bilingual comparison; 320px layout with large text; 50 preview cycles; 100 alternating resource/learner/text/support changes; 200 unique navigations; 50 immersive open/close cycles; native Audio playback through the karaoke overlay; and reading-place scrolling. Fixture generation is deterministic and every support anchor is checked against the exact source substring. The runtime records accepted original/adapted supports and canonical sentence counts.

`original-supports-200` keeps the adapted reading active while attaching 200 supports to its original-source history entry. It measures source-owner validation/selection alongside adapted immersive rendering, not the protected original-reading DOM path. `comparison-supports-200` also renders the original source pane and its supports.

`protected-original-supports-200` and `protected-original-phone` render the actual protected original reader with 200 inline supports. The phone case uses a 320px viewport and the fixture's 24px root setting. Before measuring, the runner exercises word-help visibility and lighter density, checks exact source text (including whitespace) after removing inserted controls/supports, and restores all supports. These correctness interactions are outside the measured sweep window. `originalReader` in the report records the verified support counts and source-preservation result.

Use `--case protected-original-supports-200,protected-original-phone --instrument` with `--baseline-ready` to run these checks. Optional `--screenshots-dir <directory>` writes one viewport PNG per selected case before measurement, plus a scrolled passage view for protected originals, and includes their paths in the report; it does not capture the full long document. Protected-original cases also reject horizontal page overflow.

Each case receives 25 sweep updates. Update-to-two-paints latency excludes the first five samples and includes animation-frame pacing, layout, paint scheduling, and machine contention. It is **not React CPU time**. Instrumented React Profiler totals cover all 25 updates. Public-helper counters exclude nested lexical helper calls. Long-task counters use the browser's long-task observer. Reset discards setup entries and rejects subsequently delivered entries that began before the measurement window; snapshot drains queued records. Unsupported metrics are null.

With `--verify-crawl-motion --case crawl-long`, the runner changes the browser's reduced-motion preference while the text is moving. It verifies a stationary, preserved position, no automatic resume when the preference is removed, explicit Play while reduced motion remains enabled, and a paused, scrollable view after closing and reopening. It restores normal preference and playback before the measured window; `crawlMotion` records the checks. These opt-in checks verify the new behavior, not paired performance: omit the flag for both sides of a timing comparison, particularly historical `--baseline-source` runs without live motion handling. Unit tests separately cover listener cleanup, retired-session callbacks, legacy listeners, and ambient-audio ownership.

The Crawl fixture opens its containing immersive reader. Earlier fixture versions set the Crawl flag without opening that parent and therefore did not exercise the overlay; do not use those reports as Crawl performance evidence.

`--verify-word-help-spotlight` adds real-browser checks for Show in text: connected CSS Highlight ranges, status feedback, immediate cleanup after a same-reading learner change, and four-second expiry. Run with `--smoke --instrument` for the teacher disclosure path, or `--case large-text-phone --instrument --baseline-ready <full-HEAD>` for the existing 320px case. The check requires at least one non-immersive adapted case with supports. It restores the learner and disclosure before counters reset, records `wordHelpSpotlight`, and does not replace the unit tests for independent readers or browsers without CSS Highlights. Omit this correctness-only flag from paired timing comparisons.

`--verify-auxiliary-audio` checks the word-help list's Listen/Stop controls in those same eligible cases. It verifies the requested explanation text and reader-owned audio ID, reserves that ID with playback still pending, checks cancellation without restarting, and confirms a fresh Listen uses a new ID. Changing the explanation text must stop its active request; changing learners must cancel its pending request. In teacher cases, collapsing the student list must cancel pending and active list speech while preserving unrelated playback; reopening must not restart it. Playback, learner, support version, recorded callbacks, disclosure and scroll are restored before measurement. The `auxiliaryAudio` result explicitly describes recorded-callback checks, not synthesized speech or integrated-host cancellation. Unit tests also cover section listening, comparison lists, language, StrictMode and preview isolation. Omit this correctness-only flag from paired timing comparisons.

`--verify-section-prompts --case section-prompts,section-prompts-phone` verifies inline section navigation at desktop and 320px widths. It checks focus transfer to the relocated selector, per-section answer retention, a reachable end-of-passage fallback for heading-only sections, disabled empty-section narration, and Close returning focus to the correct toggle. It also appends text while an inline answer has focus, checks owned focus recovery, then changes the anonymous session and verifies that a newly selected paragraph determines the section opened. With `--screenshots-dir`, it captures the fallback panel. These cases include an initial heading with no body; existing fixtures are unchanged. The check authors temporary fixture answers and restores the revision/session before measurement, so omit this correctness-only flag from paired performance comparisons. Unit tests also cover StrictMode, sibling-reader focus isolation, deliberate blur/close, session resets, Clear my work, pending timer cancellation and stable same-session tracking.

`--verify-reading-position` uses those same desktop and phone cases to mount a temporary independent reader above and below the main reader. With the main passage outside the real viewport, focusing a sibling paragraph and waiting for scroll-rest must not move the main reader's questions or bookmark to that paragraph. A primary-reader pointer check confirms its own position still works. The check then uses a temporary named learner, authors an answer and bookmark, scrolls to save a later position, and switches learners away and back to produce the Continue offer without changing the source. Keyboard activation of Start from the beginning must focus the reader's first paragraph, leave it visible after scrolling settles, save paragraph zero without automatic resume, and open questions at the beginning while preserving authored work. After another genuine scroll-rest save and learner round trip, keyboard Continue must focus the exact saved paragraph, leave its start visible after the banner disappears, and preserve its position, answers, and bookmark. A separate named-learner check authors old-version work and changes the text: keyboard OK on the revision notice must focus the visible beginning without altering that earlier work. A further revision allows an answer and bookmark while its notice remains pending; keyboard OK must return to the current later paragraph and preserve both versions' authored work. These real-scroll checks allow valid automatic position saves after acknowledgement. The check unmounts the peer, closes its panels, and restores the learner/session, revision, and scroll before measurement; `readingPosition` records the results, including `revisedNotice` focus, visibility, and preservation flags. Writes stay in disposable fixture storage. Omit this correctness-only flag from paired performance comparisons.

The reading-position check also enables the fixture-only `mediaReading` state, which substitutes three sections with an HTML table and SVG bar chart at the end of the second section. Trusted clicks on a table cell and chart bar must select the corresponding canonical paragraph for bookmarking. Keyboard Go to bookmark and Continue must focus that media block and leave its start visible; the Continue offer is produced through a real scroll-rest save and learner round trip. Questions opened from either media block must select section two, and answers/bookmarks must survive Continue. `readingPosition.media` reports each media type separately, with optional focused-target screenshots. Resource, learner/session, content mode, panels, and scroll are restored before measurement. The small synthetic renderer exercises the production reader's media wrappers and navigation, not the full host's table/chart rendering.

For a separate native-player check, run `node dev-tools/reader_native_audio_qa.cjs --output .tmp/reader-native-audio.json`. It extracts the current host speech/stop wrappers and content-engine stop verbatim, compiles the PhaseK source, and connects them to synthetic controls with minimal host state. A low-volume loopback tone verifies advancing native playback, Stop, aborted pending synthesis, ignored late completion and restart. If an English `localService` voice exists, the script also requires real device-speech start/end events; otherwise it reports speech unavailable. It blocks external browser requests, records source/block hashes, and closes its browser/server. This complements reader DOM tests; it is not full-host integration, cloud synthesis, deployed-byte verification or acoustic listening. The local 2026-10-14 run passed native-player checks and Microsoft David device-speech events without external requests.

Instrumented `domParses` counts actual `DOMParser.parseFromString` attempts, including failed attempts. `domParseInputChars` counts their string inputs; non-string arguments are not coerced again just for measurement. `readingTextPlain` and `readingTextPlainInputChars` separately measure calls and full string inputs to the public plain-text API, not nested lexical calls. Parser attempts can include validation work, so do not treat a nonzero total as proof that the plain-text cache missed. Timing totals and operation counts describe different costs.

GC-assisted CDP heap/DOM/listener counts are recorded mounted, every ten lifecycle cycles, and after unmount plus a 4.5-second timer drain. Timer IDs and audio WeakRefs do not retain DOM nodes. Audio tracking adds one telemetry listener per Audio instance. Preview loops focus and click controls within the page to avoid retaining locator element handles; karaoke uses in-page focus and trusted keyboard activation. These aggregate counters detect trends; a detached-node leak requires a heap snapshot and a retaining path.

Each case also records `cleanupBaseline` before the reader's first render and `immediatelyAfterClose` in the same browser evaluation as unmount. Immediate and delayed snapshots must not exceed the fixture baseline for timers, animation frames, playing audio or highlight ranges. Timer/frame checks require `--instrument`; unavailable metrics are not reported as zero. Active MutationObserver instances are counted using weak references after successful `observe` until `disconnect`, and reported separately rather than mistaken for reader-owned infrastructure. No observer targets are retained by this instrumentation.

For the added coverage, run `--instrument --case crawl-long,original-supports-200,comparison-supports-200` with the normal `--baseline-ready` argument. Keep `--retention --case unique-navigation --instrument` for the existing retention checks.

The smoke case checks actual preview open/close, an immersive sentence mapping, and two comparison panes. Smoke and preview-cycle cases open the visible Teacher setup section first and wait for the preview opener to become visible; they do not invoke hidden controls. Unit tests supply stricter highlight/click/version-invalidation assertions; this fixture does not replace them.

## Limits and budget setting

### Preserved candidate review

The retired worktree is preserved under `_archive/reader-performance-preserved-2026-10-05/capture/changed-files/`. Its `reports/reader-performance-current` patches are historical evidence, not a patch queue to apply wholesale. The bounded plain-text parsing cache, overlay timer ownership, diagnostics cleanup, and Crawl paragraph reuse are already integrated and have newer regressions in the current tree.

The current reader reuses the captured source and navigation identity only within one render. Event handlers still resolve their source snapshot when invoked, and subsequent renders recompute it. This extracts the redundant-read idea without importing cross-render source/support caches or their broad serialization. Work counts are the regression guard; they do not establish a universal latency improvement.

Local before/after checks on 2026-10-14 counted 100 to 50 public snapshot calls for `long-immersive`, 125 to 75 for `protected-original-phone`, and 200 to 150 for `comparison-supports-200`, across 25 unchanged updates each. These counters exclude internal lexical calls. The phone case preserved the exact original passage and all 200 supports; all three cases passed immediate timer/frame/audio/highlight cleanup. `reader_render_cost.test.js` guards fresh render and event-time identities, while `reader_word_help_idle.test.js` checks restored marks after StrictMode cleanup/replay, identical-text DOM replacement, and independent reader/preview range ownership. The current highlight cache checks passage identity and noncollapsed ranges without adding an observer.

The broad source/support caches and passage-observer experiment remain excluded because their archived comparative latency results were mixed. Duplicate-position write suppression also remains excluded: it changes saved-place recency and can bypass legacy-row normalization. Current scrolling already deduplicates the same paragraph and debounces persistence. Keep existing recency, recovery, migration, and cross-tab reconciliation tests when considering future storage changes.

Adapted word-help actions now scope pending feedback to the committed reading owner, exact passage, language, and learner/viewing mode. Late completions cannot publish notices, move focus, or clear a newer action's busy state after that context changes. Same-session support updates still complete normally, and a synchronous pending flag suppresses duplicate actions. `reader_word_help_requests.test.js` verifies these boundaries, valid retries, and StrictMode behavior through the full reader. These guards do not cancel host requests or change saved support/draft ownership; the host's persistence validation remains separate.

Original-reader manual suggestions, automatic suggestions, and AI-help removal now use the same ownership boundaries. A scoped pending guard prevents duplicate manual actions and overlapping removal/generation. Removal stops issuing additional calls after navigation or unmount; an already-issued host call is not cancelled. Automatic runs still finish and retain their existing once-per-source and daily-limit bookkeeping. Keyed status subscriptions let a reopened reader observe completion without replaying the old reader's transient notices. `reader_original_word_help_requests.test.js` and `reader_original_word_help_auto_requests.test.js` cover navigation, learner/language/mode changes, StrictMode replay, reopen during a pending run, and educator/pinned support preservation.

Batch removal rechecks the latest committed supports, item, and callback before each step. Its initial target IDs and text anchors stay fixed, so later educator edits, pins, removals, reanchoring, and newly added supports are respected. This protects the boundaries between asynchronous callbacks; it is not an atomic conditional write inside a host callback's own deferred persistence. Spotlight status now clears with its four-second highlight or a reader/presentation/support change. Context changes also clear locator messages in browsers without CSS Highlight support. These changes add no observer and preserve unrelated readers' highlight ranges.

Word-help lists and section listening treat the host's reserved audio ID as an active request even before speech starts, so Stop cancels pending synthesis instead of submitting it again. The gloss editor clears old save/error feedback and deferred focus requests only when its passage key changes. Drafts remain available for review, valid appended-text edits still save, and initial draft recovery can still report a removed explanation. Regression tests cover both original and adapted editing, including source replacement while a save or discard decision is pending.

Auxiliary speech now owns a distinct ID per reader instance and activation. Its local cleanup stops only that matching request when its reader context changes, the spoken word help changes or is withdrawn, the teacher collapses the student list, the selected section changes or closes, or the reader unmounts. Collapsing the list also clears its temporary locator feedback while preserving permanent word marks and section speech; the spotlight browser check asserts this after the next paint, before normal expiry. Equivalent support metadata and ordinary rerenders preserve playback. The existing general ID/text navigation stop remains separate. Prepared-help cards use the full artifact-instance/family/unit identity and learner-session context, so copied readings or anonymous class-session switches cannot retain the previous card or its audio. These changes add no observer or timer; tests cover independent readers, unrelated replacement playback, stable sessions, and return navigation.

Icons, references UI, and some host callbacks are stubs. Ordinary `handleSpeak` records calls; native karaoke Audio is exercised only with a local one-second fixture response. Full-host TTS, late cloud callbacks, audio ownership across navigation, CSP, production asset pins, and deployed-release behavior need integration verification. The large-text case changes fixture root and immersive font settings; verify the user's complete browser zoom/preferences separately. Reading-place writes occur only in disposable storage. There is no learner data in these fixtures.

Use work-count invariants as immediate regression guards: no full hidden-passage formatting or adapted-support validation solely for unchanged immersive sweep updates; only active-sentence word rendering; no sweep-driven storage writes; exact invalidation when resource, learner, text, or supports change; zero active audio/highlight ranges/timers/rAF after close. Allow the existing root/browser listeners when comparing unmounted snapshots. Compare lifecycle counts after warmup and investigate a sustained slope, not a single retained snapshot.

Do not turn one timing run on a busy workstation into a hard CI threshold. Repeat alternating baseline/candidate runs on a named target device after integration and correctness stabilization. Set per-fixture p50/p95 latency, React render-time, long-task, retained-heap, and listener envelopes from the measured distribution and noise; retain both the representative 300-sentence case and the 3,000-sentence stress case. There is no claim that the stress case meets a 60fps budget.
