# Export acceptance bug review

Read-only local Chromium probes against the current export acceptance tool. No application source was changed. The evidence file records the implementation hash, exact synthetic HTML/contracts, every checker result, and independent Chromium role counts.

1. **Exposed table semantics are not checked (P2).** `dev-tools/document_export_at_acceptance.cjs:59` and `:77` records DOM table cells, tag names, and scope values. Adding `role="presentation"` or `aria-hidden="true"` to a correctly marked-up table still passes every check with complete coverage. Independent Chromium inspection exposes zero tables and zero column headers; the control exposes one table and two column headers. Thus the automated report can claim table/header acceptance for a table unavailable to assistive technology. Verify the selected table and its required header cells through exposed roles, preserving the existing cell/value checks.

2. **Relative CSS dependencies can disappear without incomplete coverage (P2).** `page.setContent` at line 44 leaves the document on `about:blank`; resource enumeration at line 138 examines elements/attributes only. A visible block with `background-image:url(required-chart.png)` passes all checks with zero blocked/unresolved resources even though the relative image cannot load. A fulfilled isolated document origin would make relative resource requests observable while retaining network blocking; retain explicit checks for resources that are never requested. This finding concerns resource completeness, not a claim that the checkpoint contract assesses all figure meaning.

3. **Canonical-equivalent table text is falsely rejected (P2).** Lines 73-77 normalize actual cell text to NFC but compare it with the unnormalized expected matrix. A document and contract both containing the identical decomposed string `Cafe\u0301` fail `html.table-1`, despite correct native roles and no change in content. Normalize both sides consistently with NFC; keep compatibility distinctions such as superscripts intact. The positive Unicode regression currently covers reading anchors only.

4. **Inert data blocks are reported as executable dependencies (P3).** Line 114 allow only JSON/plain-text script types. A `script type="application/xml"` data block makes coverage unavailable with `script-dependent-content`, while independent Chromium with document JavaScript enabled confirms that its body never executes. Distinguish actual JavaScript/module/import-map behavior from other inert data-block MIME types or report an unsupported-type limitation without claiming execution dependency.
