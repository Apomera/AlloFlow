## Engine changes and contract

Changed sections: module-scope lookup ownership; selection capture in `handleTextMouseUp`;
the word-definition/phonics handlers and their shared lookup helpers; definition/phonics
close handlers; and `handleDefineSelection`. Source generation and revision behavior were
not refactored. `_resolveRevisionArtifactContext` remains the existing grade/language resolver.

Stable React popup setters key a module-local WeakMap. Each lookup owns a unique request
object across recreated engine instances. The live artifact ID, exact text, active view,
session identity, and AI attempt must still match before results can update the popup.
Dismissal or a new lookup invalidates the prior session, including legacy eager audio.
Dictionary results are independently owned and never erased by AI failure.

Both popup payloads now include:

- `lookupRequest`: immutable selected word/phrase, block text, character offset when available,
  occurrence, pane, saved artifact grade, language, artifact identity, and optional prepared help.
- `language`, `grade`, `preparedText`.
- `aiStatus`: `loading`, `ready`, `error`, or `disabled`.
- `dictionaryStatus`: `loading`, `ready`, `unavailable`, or `unsupported`.
- `retry()`: retries AI against the original captured request; keeps dictionary/prepared data.
- Existing `word`, `text`/`data`, `dictionary`, position, and `isLoading` fields remain usable.

These are transient popup values, not saved artifact fields. Do not serialize the callback.
English single words retain dictionary lookup; multiword/non-English lookup remains unsupported
by the existing dictionary service. Missing/rejected dictionary requests settle independently.
AI-disabled word, phrase, and phonics paths do not call AI. Empty definitions and malformed or
unusable phonics JSON become retryable errors. Phonics properties are normalized before rendering.

Word/phrase prompts use the saved artifact's grade and captured passage instead of ambient grade
or topic. Phonics prompts receive the selected occurrence context. The existing
`data-reading-language` recovery is preserved; there is no redundant renderer language-argument fix.

## Reader delta

The staged adapter:

- Renders prepared text, dictionary results, loading/error/disabled states, and AI retry independently.
- Makes word synthesis and dictionary recordings available without successful AI analysis.
- Offers `Hear in passage` using the captured block and its language for contextual pronunciation.
- Carries prepared text into `More about this word` so provider failure cannot remove visible help.
- Passes the saved language as `handleSpeak`'s fifth argument; offers a separate English listener
  when the generated response contains the requested English-translation marker.
- Invalidates audio by request identity, including identical spelling in another pane.
- Closes lookup sessions on reader unmount/comparison switch; retains existing artifact/mode cleanup.
- Connects drag-selection to the existing Define menu in normal and exact renderers, preserving
  the captured phrase when menu focus clears the browser selection.

Track 17 language handoff: existing language names and the fifth speech argument remain the contract.
The primary definition and marked English translation use separate audio controls. Dictionary
recordings remain dictionary-owned. Provider accent/semantic quality was not evaluated with live AI.
The adapter uses the existing translation fallback convention for new `simplified.lookup_*` strings:
`ai_disabled`, `loading`, `ai_failed`, `retry`, `dictionary_loading`, `dictionary_unavailable`,
`listen_english`, and `hear_passage`. Add localized values through the language owner's workflow.
