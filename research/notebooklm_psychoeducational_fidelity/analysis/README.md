# Analysis and Reproducibility Workflow

Status: planned; no analysis has been run on NotebookLM study outputs.

## 1. Analysis principles

- Treat cases as the primary sampling units.
- Account for claims nested in outputs and outputs nested in cases.
- Emphasize effect estimates and uncertainty intervals.
- Keep confirmatory, sensitivity, and exploratory analyses distinct.
- Preserve raw data; derived datasets are generated by scripted transformations.
- Test every derivation against small fixtures with known answers.
- Never silently discard refusals, truncations, platform failures, or unscorable cases.

## 2. Planned pipeline

1. Validate case JSON and claim ledgers against their schemas.
2. Verify file hashes and manifest uniqueness.
3. Import untouched output text and annotation tables.
4. Check referential integrity among cases, outputs, claims, citations, and omissions.
5. Produce a blinded data-quality report before outcome modeling.
6. Lock the confirmatory dataset.
7. Run the frozen primary model.
8. Run prespecified secondary and sensitivity analyses.
9. Generate tables and figures from code.
10. Export a machine-readable results ledger for manuscript drafting.

## 3. Proposed software

R is proposed for the confirmatory statistical analysis and figures. Python or Node.js may be used for deterministic document rendering, hashing, and schema validation. Exact versions and packages will be frozen before confirmatory collection.

Likely R functionality:

- Mixed-effects logistic regression.
- Marginal probabilities, risk differences, and risk ratios.
- Case-cluster bootstrap intervals.
- Chance-corrected interrater reliability.
- Reproducible tables and graphics.

No package is considered approved merely because it appears here. Versions, estimators, convergence rules, and fallback models will be documented in the frozen analysis specification.

## 4. Primary analysis dataset

One row per eligible atomic claim, joined to:

- Case features.
- Output metadata.
- Prompt condition.
- Repetition.
- Report section.
- Dominant task demand.
- Final adjudicated support label when available.

Primary binary outcome:

- `1` for `UNSUPPORTED` or `CONTRADICTED`.
- `0` for `SUPPORTED`, `CONFLICT_PRESERVED`, or `PARTIALLY_SUPPORTED`.
- Missing for formally adjudicated `UNSCORABLE`.

A sensitivity analysis will recode `PARTIALLY_SUPPORTED` as `1`.

## 5. Primary model specification, draft

Conceptual formula:

```text
claim_error ~ 1 + (1 | case_id) + (1 | output_id)
```

The standard-prompt marginal claim-error probability is the primary estimand.

If the guardrail comparison is confirmatory:

```text
claim_error ~ prompt_condition + (1 | case_id) + (1 | output_id)
```

The final implementation will state link function, estimator, optimizer, convergence criteria, marginalization method, and confidence-interval method.

## 6. Precision and sample-size simulation

Before confirmatory collection, a simulation script will vary:

- Number of cases.
- Outputs per condition.
- Claims per output.
- Baseline error probability.
- Case-level and output-level intraclass dependence.
- Condition effect size.
- Missing or truncated output frequency.

The final case count will prioritize precision for the standard-prompt error rate and feasibility of qualified human annotation. Pilot outcomes will be used only for nuisance parameters and burden estimates; pilot cases will not enter confirmatory estimates.

## 7. Reliability analysis

Reliability will be reported for:

- Support category.
- Binary primary error label.
- Severity.
- Omission category.
- Citation entailment.

Raw agreement and a prespecified chance-corrected statistic will both be reported. All major or critical labels and all disagreements entering the primary numerator will be adjudicated.

## 8. Planned result displays

- Overall source-support distribution.
- Case-level unsupported-or-contradicted claim rates.
- Report-level major or critical failure rate.
- Error rates by task demand and report section.
- Citation entailment versus claim support.
- Missingness and conflict-handling outcomes.
- Paired standard-versus-guardrail differences by case.
- Across-run conclusion and error stability.
- Human-intervention burden across research stages.
