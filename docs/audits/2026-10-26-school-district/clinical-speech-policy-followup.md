# Clinical speech, media ownership and policy validation

October 26, 2026. Continued local security improvements for Gemini Canvas and the proposed Portland Public Schools, Maine K–12 workflow. This pass follows the [clinical file-action corrections](clinical-file-actions-followup.md). The separate release/build, private runtime-loader and cloud workstreams were checked read-only and were not repeated. All findings and tests use synthetic records.

## Reproduced findings and changes

**Clinical read-aloud bypassed the clinical transmission boundary.** Dynamic Assessment passed custom item text, scaffold text and language drafts directly to the shared host speech player. The actual mounted component and shared player sent a synthetic custom prompt to `callTTS` while clinical external AI was disabled. Locking or unmounting did not abort that pending request, prevent later audio playback, or clear the shared player's readable `currentText`.

Clinical assessment read-aloud now uses its own browser speech adapter. It explicitly selects a matching voice whose `localService` value is `true`, with no shared-player, cloud, prefetch or provider fallback. Missing local capability or a matching voice produces an explanation instead of silently selecting a remote voice. Each utterance is tied to the protected epoch and current case/item. Lock, close, context changes and mute stop owned playback; completion and cancellation clear the held utterance text and handlers. Existing ordinary-tool speech behavior is outside this change. Calling a local preference in the shared player was insufficient because that route could still fall back to cloud.

**Clinical dictation outlived its view and student.** Actual React reproductions showed both BehaviorLens Session Notes and Voice to ABC continuing browser recognition after unmount. After changing students, an old recognition result could appear in the new student's draft. The shared voice helper did not supply a clinical cancellation or processing-location contract.

These tools now require explicit browser on-device recognition support. They check the actual `processLocally` capability, set it to `true`, and require installed US English (`en-US`) reported as available for local processing. No language pack is automatically installed, and there is no shared-helper or remote-recognition fallback. Typed notes and editable observation text remain available. The asynchronous availability check and recognition callbacks remain bound to their initiating session and student; stopping, locking, closing or switching students invalidates the old run. Completed drafts belong to their student rather than carrying into the next student's fields.

**Loaded media could carry into another student's view.** The actual IOA Calculator retained a selected audio file and live media URL when the student changed, although ordinary unmount already revoked that URL. The calculator now owns its media resources within the selected student context. Preview playback, file reads, Blob URLs and audio-analysis contexts are released when that context ends or the media is replaced. Late results cannot repopulate a later view. Typed observation/coding work uses the existing protected per-student draft facilities.

**Removing media during review did not cancel pending transmission.** Independent review found that a media-selection check before the editable AI review, followed by another after the provider response, still allowed an old recording to proceed during that delay. Every IOA media route now carries its initiating file/generation check through the text or vision review wrapper and the existing protected request controls. The check runs before review, after approval, during provider preparation/attempt dispatch, and before accepting the response. Replacing, removing or leaving the recording cancels the pending operation, including text-only fallbacks. Already dispatched provider requests cannot be recalled by these checks.

**Refused or failed BehaviorLens downloads retained temporary output.** A refused export revoked its Blob URL but left the body-level link attached; a native click failure or non-cancellation policy error left both the link and readable Blob URL. The shared download helper now revokes the failed output URL and removes its link/href while preserving the original cancellation/error result. Successful handoff retains the existing caller's cleanup behavior. This does not retract a completed download.

**Malformed configuration could enable clinical access.** Actual encrypted-service tests demonstrated acceptance of inherited version/Canvas approval, accessor-based approval, and inherited AI permission arrays or strings. Policy validation now reads bounded own data properties and validates dense, unique feature lists. Unsupported fields, accessors and inherited settings fail closed. Retention settings use the same strict representation; malformed settings cannot authorize deletion. Plain or null-prototype explicit configuration remains supported, and existing defaults are unchanged. Saving and locking already-open work remain possible when access policy becomes invalid.

This last finding is malformed-configuration hardening. It is not evidence of a remote exploit, a district authentication service or isolation from arbitrary same-origin scripts.

## Browser contracts and availability

The Web Speech specification distinguishes local and remote synthesis through `localService`, and provides `processLocally` to require local recognition. These changes rely on those browser contracts; they do not independently attest the browser or operating system. [Web Speech specification](https://webaudio.github.io/web-speech-api/)

Recognition support varies. Microsoft's current documentation describes its on-device implementation in Edge Canary/Dev with explicit feature setup. A normal district browser or Canvas iframe may lack the necessary capability or permission. The application therefore keeps typed input available and does not change browser flags or install models. Verify the actual managed browser before enabling clinical voice workflows. [Microsoft's on-device recognition documentation](https://learn.microsoft.com/en-us/microsoft-edge/web-platform/speech-recognition-api)

The browser synthesis API cancels its queue globally. Assessment cleanup calls cancellation only while it owns an utterance, but another browser utterance queued concurrently may also stop. The adapter does not inspect or clear the shared host player's text or cache.

## Validation and delivery

**479 unique focused tests passed across 28 files**, with **48 native Edge checks** and **9 scoped asset/host integrity checks** passing. All three runtime/public mirrors match, runtime modules parse, and the three hosts parse. Independent review covered the local speech adapters, media ownership, guarded dispatch and download cleanup; root also reviewed strict policy parsing.

The aggregate uses the final 155-test BehaviorLens batch, the unchanged policy (108) and assessment (115) suites, 25 media-dispatch regressions, and 76 compatibility checks. It excludes duplicate runs. Initial fixture failures and the deliberately deferred public-mirror mismatch were corrected and replaced by successful final results. One initial native speech error-status assertion ran before the React update; the harness now waits for that update, and the final run passed without a production change. Baseline negative controls and initial diagnostics remain preserved separately.

The [validation record](clinical-speech-policy-validation.json) retains negative controls, exact reviewed/tested source hashes, candidate reports and native-browser evidence. Recognition and synthesis engines are simulated; the media preview check plays a muted, generated silent WAV. The tests do not capture a microphone, use real student recordings, install models or send clinical text to a provider. They verify application decisions and lifecycle handling, not production recognition accuracy or a managed browser's offline behavior.

Source/public mirrors and scoped host integrity approvals are updated together for the three changed runtime modules. Broad host-policy reconciliation, release builds and deployment remain separate. Existing host/canonical-policy differences are recorded rather than represented as resolved.

Nothing was committed, pushed or deployed, and no district/cloud account or browser security setting was changed. Default Canvas real-record access and clinical external AI remain blocked. A verified release, actual Canvas/managed-device checks and PPS approval remain required before sensitive-record use. Already transmitted provider copies, downloaded files and completed output remain outside these local cleanup controls.
