The browser queues final `dataavailable` and `stop` events when recording stops; `inactive` is therefore insufficient evidence that all callbacks have finished. See [MDN MediaRecorder.stop](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop) and [stop event](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop_event). The source fixes guard that boundary rather than depending on a particular event delay.

Existing safeguards and nonfindings:

- Original, Adapted and Both already expose narration management separately from text editing. Original text remains protected. Analysis → Read with supports → Original already provides the supported-reading path; this change does not create a competing source-copy or TTS store.
- Existing sentence identity options, human-teacher source, duration, two-minute limit, device-readiness/retry UI, teacher eligibility and focus return are preserved.
- The current host bridge accepts options at [AlloFlowANTI.txt:32883](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/.tmp/reader-recording-lifecycle18/basis/AlloFlowANTI.txt:32883), and the service forwards cancellation at [read_aloud_audio_service_source.jsx:653](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/.tmp/reader-recording-lifecycle18/basis/read_aloud_audio_service_source.jsx:653) and [1452](C:/Users/cabba/OneDrive/Desktop/UDL-Tool-Updated/.tmp/reader-recording-lifecycle18/basis/read_aloud_audio_service_source.jsx:1452). No API extension is needed.
- Cancellation is cooperative. It does not roll back already committed persistence, and the legacy host fallback does not consume the AbortSignal. This patch does not establish transactional storage cancellation or durability after restart.
- A failed captured take is not retained by this patch for a later recording-save retry. Preserving that take safely is a separate reader/service recovery improvement; existing device retry applies when audio is already available in the service.
