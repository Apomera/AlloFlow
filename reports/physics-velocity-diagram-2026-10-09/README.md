# Recorded velocity components

The Motion view now connects its recorded readings to a velocity diagram in the Position & velocity card. A dashed horizontal component followed by a dotted vertical component reaches the same endpoint as the solid resultant arrow. Signed axes, an arrow key, the recorded time, and the speed equation explain how the picture relates to the readings.

The diagram reads the selected observation and its captured flight. Editing the next launch or reopening an older recording preserves its velocity, scale, and CSV data. Speed uses the original `Math.hypot(vx, vy)` snapshot value.

## A scale shared across the flight

The diagram scans every original observation in the selected trail to find its greatest recorded speed. Its circle radius represents that speed. Arrow lengths therefore remain comparable between moments of a completed flight. A growing unfinished flight can add a new maximum; the visible explanation states that its scale updates as points are recorded.

Each endpoint is computed from the signed components using the same scale. Zero components have no arrow and receive a visible explanation. At an apex with horizontal motion, the card explains why speed remains nonzero. Tiny nonzero components keep proportional lengths and arrowheads, with their sign and size retained in the numeric readings. The implementation does not apply a minimum arrow length.

The larger solid arrow is drawn before the component arrows, keeping both visible when they overlap at horizontal or vertical motion. Line patterns and the visible key supplement the theme colors. The scale circle has a contrasting dashed stroke. The card places the diagram beside the readings on wide screens and stacks them on narrow screens.

The SVG is a static accessible image, with the actual recorded time and velocity values in its label and references to the visible explanations. Existing chart keyboard controls and the sample status remain available.
