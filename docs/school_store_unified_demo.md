# AlloFlow: one simple administrator demo

Use this entry point for the presentation. It replaces the earlier separate prototype/demo tabs as the recommended route, while preserving them for engineering history.

From the AlloFlow repository, run `npm run demo:alloflow`, then open [the demo](http://127.0.0.1:8767/). Keep its terminal running. No Google login, API key, Classroom setup or manual class-link preparation is needed. Use fictional data only.

## Five-minute route

1. **Prepared class:** the fictional class and reviewed links are already present. Explain that Classroom can reduce roster setup; this demo uses a prepared fictional snapshot, not a live Google import.
2. **Recognize:** choose the prepared example for Calm Otter (Avery), worth five points. Review the matched school student, use the student in the award form, and confirm the award. Avery starts with 60 and now has 65.
3. **Student balance:** show Avery's updated balance and recognition history. The role change is a simulation, not a Google sign-in.
4. **Shop:** choose Avery, add one Notebook costing 10 points, review and confirm checkout. Avery now has 55 points and four Notebooks remain.

After checkout, choose **Preview student email** beside the receipt. It shows the exact subject, fictional recipient, formatted email and plain-text message generated by the Store for that purchase. The message is captured locally, **not sent**. Email apps may render its formatting differently. Close the preview to return to the receipt; no email address or Google setup is needed.

Previewing never resends mail or changes points. A refund has its own separate email. Reset clears captured messages along with the fictional transactions; older tabs must reload. This preview is a unified-demo feature, not a live email-sending service.

Email-preview verification: 117 unified-demo tests passed, plus both full desktop/mobile browser rehearsals. The rehearsals checked the exact purchase email, 55-point balance, plain text, isolated HTML, explicit opening/closing, and unchanged Store state. Preview screenshots are `email-preview-1280.png` and `email-preview-390.png` in the report folder below.

Use the numbered navigation in the same tab. Advanced role controls, reset and the longer Print Lab/design walkthrough are optional; they are not prerequisites for this presentation. No receipt email or printer command is sent.

## Rehearsing again

**Reset fictional records** restores the starting balances, stock, students and reviewed class links. It affects only this local in-memory demo. Other open tabs from an older reset are blocked from writing until reloaded; the current page returns to the start. Restarting the server also creates a fresh fixture.

For a dependable presentation, use the typed example. Dedicated on-device voice is optional and is not started automatically or simulated in the presentation. Its actual browser/microphone compatibility remains unverified; there is no need to demonstrate voice to show the points workflow.

## What is real, and what is simulated?

The screens and validation/ledger operations are the actual School Store code. Google identity, Sheets/Drive, locks and mail are simulated; the three people, class links and balances are fictional. The presenter controls navigate and prepare input, but never automatically award points or finish a purchase. This is demo packaging around the product, not a replacement app or a claim of school readiness.

Canvas/desktop launches the managed Store; Classroom roster authorization does not grant Store permissions; Educator Evaluation remains a separate personnel tool. The unified demo simplifies navigation, not those permission boundaries.

The longer original administrator route remains available using `npm run demo:school-store -- --legacy`; see [Store + Print Lab walkthrough](school_store_admin_walkthrough.md). Live deployment, real student data and microphone testing still require their own approval and checks.

It blocks external requests and does not grant microphone access or supply a fake working speech recognizer.
