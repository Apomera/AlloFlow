A packet file can:

  • Run Concept Sort, Sequence Order, Tiered Writing (with 3 scaffold levels), or a multi-path UDL Choice Board offline in one file.
  • Show optional home-language directions, reading tools, and a printable writing sheet.
  • Keep the student's place on that device, and save results as CSV, JSON, or an optional sealed QR code.

A packet file cannot:

  • Run AI. Nothing is generated when you make a file or when a student uses it.
  • Connect to the internet. The file tells the browser to refuse every connection, and the browser enforces it.
  • Read other files on the student's device or send data without the student saving or sharing results.

The rule this page gives your browser. The browser refuses anything the rule does not allow: It is the Content-Security-Policy line near the top of this page's source.

    1. Send the file to students through your learning platform, a shared drive, or a USB drive. From Google Drive or Google Classroom, students download the file first because the preview does not run it.

    About this page

    What this page keeps

    Your last choices and draft content are kept in this browser so that the page opens where you left off. A student's code name is never kept. Nothing is sent anywhere.

    How these packets work

    • Every packet is assembled in this browser tab as one standalone HTML file with a strict zero-network policy.
    • UDL Choice Boards hold 2 to 3 pathways aligned to one learning goal so students can choose how to demonstrate understanding while teachers receive both mastery and chosen-modality records.
    • Tiered Writing includes 3 student-toggleable scaffold levels, live word counting, a self-check rubric, and a clean print view.
