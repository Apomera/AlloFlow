The teacher mailbox effect can publish stale connection state after a reconnect or teardown. Its `answerRtcOffer` closure awaits remote-description installation, answer construction, local-description installation, and ICE completion without rechecking either effect cancellation or the installed peer's identity. The poll checks cancellation once after receiving the batch, then awaits an offer without checking cancellation before later batch entries. A disposed effect can consequently send an old SDP answer and apply following roster/evidence records.

Peer callbacks have the same gap: an old channel's message, open, close, or late datachannel-registration callback remains callable after replacement. In particular, an old close callback can change the replacement's roster entry from `rtc: true` to `false`. Old messages overwrite the current learner's name, device evidence, or trigger the bridge nudge. The late-join welcome starts asynchronous image preparation and encoding and continues draining chunks after its owner is retired.

Network/visibility wake callbacks schedule `poll` while an earlier receive or offer remains pending. The effect has no in-flight latch. Multiple receives can therefore use the same shared cursor and apply overlapping batches. An effect-local latch and coalesced immediate follow-up preserve wake responsiveness without concurrent receives. Cancellation must release the latch and suppress the follow-up.

The proposed correction is an effect-cancellation guard plus exact peer and channel ownership checks at callback entry and each await boundary, a per-entry poll cancellation check, and one serialized receive with a coalesced wake request. Current controls must still negotiate a channel, apply learner/evidence records, handle current nudge/open/close callbacks, and send each welcome chunk.

`teacher-connection.node.cjs` executes the extracted production effect verbatim. It controls RTC methods, mailbox replies, resource preparation/encoding, data-channel draining, and event/timer scheduling. It writes an input hash, effect hash, and individual outcomes to the selected receipt. It does not prove real RTC connectivity or hosted mailbox behavior, and it cannot cancel an already-started external send.
