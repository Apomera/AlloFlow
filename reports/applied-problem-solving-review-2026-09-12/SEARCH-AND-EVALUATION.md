# Applied Problem Solving: outside evidence and live evaluation

Search is useful when a learner’s option depends on a missing factual premise, current information, or an outside source. It should be an optional part of Explore. It adds little to ordinary reflection or coaching, and a search ranking cannot settle a question about values.

## Implemented

The collapsed **Find outside evidence** panel accepts a learner-written query of up to 200 characters. It reuses the app’s `WebSearchProvider.search(query, 5, query)`. It sends only that query, with no automatic inclusion of the lesson, learner draft, profile, or artifact links. No AI answer is generated by this step.

Up to five results show a source link, domain, preview snippet, provider, and retrieval date. The panel explains that retrieval date is not publication date. Google-backed results are labeled **Google results via Serper**; SearXNG and DuckDuckGo fallbacks retain their actual names. Results are rendered as text and safe HTTP(S) links.

**Add reference to my evidence** adds a bibliographic reference to an existing learner evidence row, with **Needs checking**, a blank claim, and no lesson-fact connection. It does not copy the snippet as learner reasoning. The learner explains what the source supports or challenges. Focus moves to that new claim. References use the existing save, submission, print/export, undo, and text-backup mechanisms.

Search results and queries remain session UI state. Only an explicitly selected reference enters saved work. Profile/resource changes clear that state, and late responses cannot populate a different workspace. Runtime restrictions, missing providers, offline results, empty results, failures, timeout, duplicates, and the 12-row limit have explicit handling. A paper-only organizer can inspect source links without adding a hidden evidence row.

## Why reuse this search path

The app has two related paths: native Gemini Google Search grounding, and its backend-independent `WebSearchProvider` retrieval chain. This feature uses the latter, which can retrieve links without having AI write a solution. It does not change Analyze Source Text, Assess, or their grounding behavior.

Native Gemini grounding lets the model decide whether to search and can return source citations and search suggestions. That remains a possible future option for a teacher-requested synthesis, but it requires preserving the provider’s attribution and response contract. It is unnecessary for this bounded source-discovery step. See [Google’s grounding documentation](https://ai.google.dev/gemini-api/docs/google-search).

The live check used the production provider code and the existing Canvas compatibility proxy. One public query, `site:usgs.gov soil infiltration runoff`, returned three results through Serper. One result was a Water Science School explanation and two were technical research publications. This illustrates why relevance, reading level, and applicability still need review; the first-ranked result should not be imported automatically. The check did not verify every snippet or browser CORS. Details: [live-search-results.json](live-search-results.json).

## AI evaluation status

Ten reproducible cases are prepared in `dev-tools/run_applied_challenge_live_pilot.cjs`:

- Five generation cases: Investigate (grade 3), Design (grade 5), Decide (grade 8), Propose (grade 10), and Explore (grade 12), with short sources and explicit missing measurements, costs, or local evidence.
- Five coaching cases: a planned check with no result, linked work that AI has not inspected, a consequential sixth evidence row, unsupported budget/demand claims, and a reasoned values question.

Generation runs the actual dispatcher branch, including its single structural repair. Feedback uses the production prompt builder. Each case contains human-review questions for lesson dependence, alternatives, feasibility, age suitability, useful feedback, uncertainty, and learner ownership. Structural validity alone does not establish educational quality.

The live run is **blocked by missing provider configuration**. No Gemini, OpenAI, or Claude credential was available to the supported CLI adapter. Standard local Ollama and LM Studio endpoints were unreachable. The app connection could not be inspected through the available browser tools. **Zero model calls were made; no AI-quality result is claimed.** The saved report leaves every case unrun and every human review pending: [live-ai-evaluation.json](live-ai-evaluation.json).

To run after configuring a supported provider in the environment:

```powershell
node dev-tools/run_applied_challenge_live_pilot.cjs --execute --backend gemini --model <configured-model-id> --max-calls 12
```

Use `GEMINI_API_KEY`, `GOOGLE_API_KEY`, or the adapter’s `ALLOFLOW_PILOT_API_KEY`; credentials are never printed or written to the report. Omitting `--execute` prepares cases without network calls. The run caps logical calls and HTTP attempts at 12 and disables retries. A repair consumes the same budget. The CLI adapter uses text mode with the production JSON instruction, so a later in-app comparison should include the app’s JSON-mode behavior.

The next human step remains the prepared [learner trial](LEARNER-TRIAL.md). No participant sessions, learning gains, or real-generation quality have been inferred from interface tests.
