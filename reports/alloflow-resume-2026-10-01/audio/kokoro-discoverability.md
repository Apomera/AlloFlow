Read-only Kokoro discoverability recommendation

Smallest useful addition: a single secondary action inside the existing expanded Audio details/preparation region, alongside the selected-voice/model explanation. Show it only when this reading is English, a Kokoro voice is not selected, no sentence/model job is running, and the loader is available and supported. Keep the collapsed reader summary unchanged. Reuse the current loader and voice selector rather than adding another engine picker.

Suggested copy: Prepare Kokoro on this device. This is more precise than Prepare with Kokoro on this device if clicking only prepares the model. If the latter label is preferred, it should open the existing setup controls and explicitly explain model preparation before sentence clips. On-device readiness may replace the action with Kokoro ready and an optional Use Kokoro action that requires user choice. Preparing the model must not automatically select a voice, change the configured speech provider or regenerate existing clips. Do not automatically download when the panel opens or when another engine fails. A failed cloud preparation may show the same secondary action for eligible English readings without an automatic engine swap.

State wording: determine current-session ready from window._kokoroTTS.ready. Read AlloModules.AlloCommands.modelCache.hasKokoro() harmlessly to distinguish Stored model; load for this session from Not stored; about 88 MB download if choosing to prepare. Cache presence is separate from a ready runtime and from saved sentence clips. After a user starts preparation, display loading/downloading/progress and retryable failure inline. Retain the existing independent device-audio saved/readback counts. A ready model does not prove offline clips have been saved. Do not claim Kokoro is more reliable; no live inference/reliability comparison was performed.
