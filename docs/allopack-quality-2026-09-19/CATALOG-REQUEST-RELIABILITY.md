# Catalog request reliability — 2026-09-19

The catalog now checks HTTP status before either downloading a lesson or passing it to the app. Previously, Download JSON could save a JSON server error response as a lesson, while Load in AlloFlow displayed success as soon as it called the host's asynchronous import bridge.

## Changes

- Both actions use the same request/parser path. It rejects unsuccessful HTTP responses, invalid JSON, non-object lessons, and malformed AlloPack envelopes or resource rows. UTF-8 BOM-prefixed JSON and approved-submission wrappers are supported. Valid objects and image fields are returned intact.
- The current host bridge returns no import-completion result. The catalog now defers completion notifications to that host rather than claiming success itself. Explicit successful callback results are supported; false results, thrown errors, and rejected promises are reported as failures.
- Action buttons are disabled while a request is in progress, with an Opening or Downloading label on the active action. A ref guard also prevents duplicate requests before React has rerendered. Closing the catalog aborts its pending lesson fetch.
- A persistent inline alert names the lesson and request error, alongside the existing toast. Starting another request clears the old alert. Buttons become available again after failure.
- Failed catalog loading offers Retry loading catalog. Retry retains filters and returns focus to the search box. Invalid manifest entries, duplicate slugs/paths, and invalid tag or display-metadata shapes now produce an error before rendering cards.
- Root and desktop/public catalog modules remain identical. Pack contents, artwork, and alt text were not changed in this pass.

## Verification scope

The production-component Chromium harness uses intercepted local responses and a recording import callback. It verifies a 503 manifest failure followed by retry, a 404 that creates no download, a malformed pack that never reaches the importer, two rapid clicks resulting in one request, an asynchronous import rejection, no premature success message for the existing void-returning host contract, a downloaded file with the expected JSON contents, and cancellation when the catalog closes. The discovery harness additionally checks natural-phrase search, grade filtering, keyboard clearing, focus, and zero-result recovery.

The lesson-parser tests cover every one of the 105 local AlloPack files without rewriting their resources. These are envelope and transfer checks; the production import/render validators remain responsible for deeper native resource semantics. A valid image reference is not proof that artwork is accurate or accessible.

No tests imported content into the user's active history or published changes to the live community library. Local fixtures were the only downloads generated by the browser test. The existing host's FileReader-based completion signaling was left unchanged.
