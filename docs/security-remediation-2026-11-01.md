## Dependency remediation

DOMPurify is now **3.4.17**, obtained from the official repository. GitHub reported annotated tag object `a307c2ac04d751cde8870191d6af503141e8c58a` as signature-verified, resolving to commit `a77a3e78b59f72fa4d1c83f22e121ad9cc7d3575`. The pinned artifact and jsDelivr, unpkg and cdnjs copies had identical bytes. This is GitHub's signature verification; this review did not independently establish local GPG trust.

SheetJS is now **0.20.3**, obtained from the official vendor artifact, not the obsolete npm publication. It replaces both 0.20.1 and the reachable 0.18.5 fallback in the reviewed runtime catalog. Lumen's same-window workbook loader was also updated. Document and backup loaders refuse obsolete preloaded versions, retain the accepted sanitizer instance, and use captured workbook readers across asynchronous work. Lumen pins the same bytes with SRI, rejects arbitrary source overrides, and retries failed/timed-out loads safely. Version checks prevent accidental downgrade; they do not authenticate a hostile same-origin script that already has JavaScript execution.

The official vendor advisories identify fixes at SheetJS 0.20.2 for [CVE-2024-22363](https://cdn.sheetjs.com/advisories/CVE-2024-22363) and 0.19.3 for [CVE-2023-30533](https://cdn.sheetjs.com/advisories/CVE-2023-30533). [DOMPurify's official release](https://github.com/cure53/DOMPurify/releases/tag/3.4.17) was used for the sanitizer update. No SheetJS-to-DOMPurify exploit chain is claimed.

PDF.js remains **3.11.174** with `isEvalSupported: false` at the application and MCP call sites covered by the regression. The review found and corrected one missing MCP flag. This preserves the [vendor-documented workaround for CVE-2024-4367](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq); it is not a general claim that the older version has no other issues. A major-version migration was not attempted blindly.
