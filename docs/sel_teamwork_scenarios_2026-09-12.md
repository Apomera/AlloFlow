# Teamwork Builder: supported scenario rehearsal

The Scenarios tab previously rated three replies from one to three stars and locked the first answer. Some feedback treated teacher support as premature, implied that a teammate must rescue unfinished work overnight, inferred motives from quietness, or treated a private conversation as inherently better than correcting public credit. Person labels also obscured the actual behavior and conditions to address.

The revised Scenarios tab keeps all ten existing scenario IDs but introduces behavior-based titles and 30 fictional setups: an elementary, middle and high-school version of each situation. The ten situations cover idea sharing, contribution access, format decisions, accurate credit, unfinished work, message repair, different forms of participation, coordination, editing and workload. Elementary introductions and rehearsal prompts use simpler language and invite reading together; the shared route explanations may still benefit from adult discussion.

Each situation offers a factual check, three possible routes with benefits and limits, changed information and a worked plan. The routes are not scored or ordered as an answer key. They are possibilities whose fit depends on context, access, power, capacity and the people affected. Asking for teacher or facilitator support is a valid first step. Repeated targeting or unsafe pressure does not require private confrontation or student mediation. Revised examples distinguish an offered turn from meaningful influence, a quiet person from a noncontributor, a factual correction from an attack, equal section counts from fair workloads, and an apology from repaired credit.

A learner may select a route, combine routes, use their own or stay undecided. Six optional note fields support observations, missing information, words or an alternative communication method, boundaries/support, a concrete next step/check-in and reconsideration. Opening examples or writing rehearsal notes adds no scenario answer, score, completion reward or practice-log entry. Other Teamwork activities, navigation badges and the optional AI coach retain their existing reward behavior.

CASEL's relationship-skills framework includes collaborative problem-solving, constructive conflict navigation, diverse settings and seeking or offering help. This broad framing informed the design. The new cases and routes are authored practice, not an evaluated CASEL program, a validated assessment or a guarantee that a script will produce cooperation. Primary source checked September 12, 2026: [CASEL, What Is SEL?](https://casel.org/what-is-sel/).

Implementation and compatibility:

- The tool ID is still `teamwork` and the tab ID is still `scenarios`. `scenarioSelections[band]` remembers the selected situation, and `scenarioDrafts[band + ':' + id]` stores a `route` and six note fields: `notice`, `check`, `words`, `support`, `plan`, `review`.
- Drafts remain independent across situations and grade bands and use the hub's existing project persistence. The user-facing copy describes the need to save/export for persistence beyond the session. No automatic copying or overwriting occurs when changing the selected route.
- The original quiz definitions remain only for interpreting historical choices and scores. Earlier answers, indices, reveal flags, reflection records, coach data and earned badges remain in project data. Recognized old choices can be viewed in a separate disclosure with a historical disclaimer; old feedback and ratings are not presented as new teaching.
- Invalid old indices, answer values and new draft field types fall back safely. Progress totals ignore invalid historical answer indices instead of indexing nonexistent choices. Unknown draft fields survive edits.
- The existing AI coach is now behind an optional disclosure. Its explicit request button, safety pre-check and response region remain. The prompt now asks for conditional options, realistic capacity, access and support without required confrontation. A mocked browser check verifies that opening the coach does not submit anything and that a request does not include rehearsal notes. A second mock check verifies that a blocked safety pre-check does not call the provider. Live provider behavior is outside this validation.
- Native labeled dropdowns and expandable panels replace the locked quiz. The revised practice uses 16px inputs, 44px minimum controls and explicit light, dark and high-contrast colors. Full situation titles remain visible below the selector, whose native option text may truncate on narrow screens.

The scoped browser and accessibility results, nine phone screenshots, historical-data checks, actual-hub return workflow, syntax and source/public parity are recorded in `reports/sel-teamwork-scenarios/validation.json`. Accessibility evidence covers the revised practice region rather than every existing Teamwork tab or the full hub. An initial test run found ambiguous text selectors matching both route panels and dropdown options; the selectors were corrected to target the panels.

No push, deployment or packaged build is included. The ignored generated `desktop/app-build` output is not rebuilt; installed copies require a fresh package to receive this source update.

Final validation: 38 focused browser checks, 586 shared/Teamwork regression checks and two selected actual-hub workflows passed (626 unique checks). Two pre-existing skips and 93 filtered hub cases are excluded. All 72 SEL tools rendered. Three scoped phone axe scans found no violations, and nine captures were visually reviewed. Syntax, scoped whitespace, original quiz definitions/IDs and source/public parity passed.
